# V2.7.8 최우선 지침 — 인물별 6뷰 통합 캐릭터시트 1장·실제 참조 필수

이 절은 아래에 남은 구버전의 단일 초상/에셋 생성 설명보다 우선합니다. 기존 대본 원문, 화풍 선택, 장면 검토, 컷 수, V2.7.5 파일명 규칙은 유지합니다.

## 1. 프롬프트 완성 후 반드시 묻기
- 최종 프롬프트 작성 및 필요한 검증이 완료되면 결과를 전달한 뒤 채팅에서 정확히 다음 질문을 합니다.
  “프롬프트가 완성되었습니다. GPT 이미지 생성 기능으로 에셋부터 본편 장면까지 자동으로 만들어 드릴까요?”
- 이 질문은 사용자에게 보내는 안내이며, Flow TXT 본문이나 이미지 프롬프트 안에 삽입하지 않습니다.
- 아직 이미지 생성을 승인하지 않았다면 답변을 기다립니다. ‘네’, ‘진행’, ‘만들어줘’ 등 동의 후 GPT 이미지 생성 기능으로 시작합니다. 이미 해당 작품의 이미지 생성을 명시적으로 승인한 경우에는 중복 질문하지 않고 승인된 범위대로 이어갑니다.
- 거절하거나 프롬프트만 요청하면 이미지 생성 없이 종료합니다. 다른 외부 유료 이미지·영상 서비스 실행 권한으로 확대하지 않습니다.
- GPT 이미지 생성 기능이 현재 환경에 없으면 가능하다고 가장하거나 생성 완료라고 하지 말고 해당 제한을 알립니다. 이 ZIP의 Python 프로그램 자체가 GPT 이미지 생성 서비스를 제공하는 것은 아닙니다.

## 2. 인물별 기준 에셋은 6분할 통합 캐릭터시트 1장
- 장면을 만들기 전에 등장인물별로 **한 장의 통합 캐릭터시트**를 먼저 만듭니다. 독립 파일 6개로 나누지 않습니다.
- 한 장 안에는 다음 6개 모습이 모두 들어가야 합니다.
  1. 전신 정면: 머리부터 발끝까지, 키·체형·의상·신발 확인.
  2. 전신 후면: 머리부터 발끝까지, 뒷머리·복식 뒷모습 확인.
  3. 얼굴/상반신 정면.
  4. 얼굴/상반신 왼쪽 45도.
  5. 얼굴/상반신 오른쪽 45도.
  6. 얼굴/상반신 측면 90도.
- 1장 안의 6개 모습 모두 얼굴, 나이, 성별, 키·체형·몸무게 인상, 얼굴 폭, 어깨·허리 비율, 머리 모양, 복식 형태·색상, 장신구 및 선택 화풍을 동일하게 유지합니다. 날씬한 인물을 장면마다 통통하게 바꾸거나 그 반대가 되면 재생성합니다.
- 캐릭터시트는 흰색 또는 연회색의 단순한 배경 위에 각 뷰가 또렷하게 분리되어 보여야 하며, 한 장만 보아도 동일 인물임을 즉시 확인할 수 있어야 합니다.
- 인물 수만큼 캐릭터시트 파일을 만듭니다. 인물 3명이면 인물 에셋은 3장입니다. 배경·소품 에셋은 별도이며, 이를 인물 캐릭터시트 안에 끼워 넣지 않습니다.
- 기존 STEP 1 UPLOAD 단일 초상 프롬프트는 Flow 인물 정의용입니다. 이것만 만들고 인물 에셋 제작을 완료했다고 처리하지 않습니다. 실제 에셋 단계에서는 위 6분할 캐릭터시트 규칙을 따릅니다.
- 파일명은 `영문ID_캐릭터시트.png`를 사용합니다. 앞에 숫자_를 붙이지 않습니다.


- 대본에 명시된 성장·변장·의상 교체만 별도 상태 시트로 제작하고 적용 구간을 기록합니다. 손·발·관절과 외형 일관성은 실제 이미지로 검토합니다.

## 3. 모든 본편 장면은 에셋 이미지를 실제로 참조해 생성
- 에셋 제작·시각 확인 완료 → 장면별 에셋 매핑 → 해당 실제 이미지 첨부/참조 입력 → 장면 생성 → 일관성 확인 순서를 반드시 지킵니다.
- 장면의 tags/subanchors/set_id에 해당하는 인물·배경·소품 에셋을 연결합니다. 인물이 없는 장면도 해당 배경/소품 기준 에셋을 먼저 만들거나 확보하고 참조합니다.
- 인물이 나오는 장면은 등장인물마다 해당 인물의 통합 캐릭터시트 한 장을 실제 참조 입력에 포함합니다. 시트 안의 전신과 해당 각도 얼굴을 참고하며 여섯 개 독립 파일로 분리하지 않습니다.
- 프롬프트에 @ID 또는 ‘에셋 참조’라고 적는 것만으로 참조 완료라고 판단하지 않습니다. 생성 기능이 제공하는 이미지 첨부·reference 입력에 실제 이미지를 전달해야 합니다.
- 생성 요청마다 컷 번호, 등장인물 ID, 사용한 에셋 파일/이미지 식별자, 실제 참조 전달 여부, 결과 이미지, 검토 상태를 작업 기록에 남깁니다. Flow TXT 안에는 이 내부 기록을 덧붙이지 않습니다.
- 필요한 에셋이 없거나, 경로를 읽지 못하거나, 이미지 참조 전달이 불가능하거나, 도구 참조 수 제한 때문에 필요한 인물을 빠뜨려야 하면 해당 컷을 중단합니다. 에셋을 복구하거나 참조 가능한 방식으로 해결한 뒤 이어갑니다. 텍스트만으로 임의 대체 생성하지 않습니다.
- 모든 장면 프롬프트에서 실제 참조 이미지의 얼굴·체형·머리·의상·색을 고정하고 장면의 행동·표정·구도만 따르도록 지시합니다. 선택한 상세 화풍 원문도 그대로 유지합니다.
- 생성된 그림을 기준 에셋과 실제로 비교합니다. 얼굴/체형/의상/색/인원 오류가 있으면 해당 에셋을 다시 첨부하여 수정하고, 검토 전 결과를 통과라고 표시하지 않습니다. 도구의 참조 입력이 동일성을 완벽하게 보장한다고 주장하지 않습니다.

## 유지 사항

- Flow 줄 형식 `003 | 원문30자 | @[에셋] 실제 프롬프트`와 기존 최종 섹션 순서는 유지합니다.

# Claude 프로젝트 지침 — 정확한 산출물 형식 고정 2.7.2 수정본 r1

## 2.7.2 수정본 r1 대본 목록 30자 표시 / 원본은 전체 보존 — 기본/절약형 공통

- `[대본 1~N]`의 각 번호에는 **그 컷이 시작되는 원문 첫 문장의 앞 30자만** 넣습니다. 40컷/100컷 모두 같습니다.
- 문장이 길면 앞에서부터 정확히 30자까지만 출력합니다. 자동으로 `...`·`…`·`이하 생략`을 새로 붙이지 않습니다.
- 원문에 실제 있는 말줄임표, 따옴표, 문장부호는 보존합니다. 말줄임표 자체를 오류로 간주하거나 무조건 삭제하지 않습니다.
- `summary`와 `script_quote`는 분석용입니다. 시작문장 대신 출력하지 않습니다. 시작문장은 `body.json[chapter.start_idx]`에서 코드로 추출합니다.
- 원본 TXT를 먼저 바인딩해 생성된 `body.json`을 사용합니다. 잘린 목록/최종 Flow TXT를 원본으로 등록하지 않습니다. `body.json`을 요약하거나 문장 뒤를 추측해 채우지 않습니다.
- 원본이 없으면 잘린 문장의 뒷부분을 창작하지 않습니다. 실제 원본 TXT를 확보할 때까지 최종 출력 PASS를 내지 않습니다.
- 최종 TXT 전달 전 원본 스냅샷·body.json·컷 인덱스의 일치와 시작문장 표시값=원문[:30]을 검사합니다. 하나라도 다르면 FAIL이며 원본으로 돌아가 수정합니다.
- 절약형은 분석 설명만 줄입니다. 캐시에 `start_sentence` 전체와 `start_idx`, `end_idx`, 원문 파일/해시를 보존합니다. 표시용 `start_sentence_30`은 원문 앞 30자로 별도 계산합니다.
- 컷 수는 사용자가 정한 N을 유지합니다. 예시의 40은 고정 제한이 아닙니다. N=100이면 두 목록 모두 정확히 1~100입니다.
- 이 패치는 화풍은행·레퍼런스 이미지·얼굴 묘사·화풍 선택 절차·최종 출력 섹션을 변경하지 않습니다.

### 내부 필수 순서
대본을 받으면 Claude가 다음 작업을 수행합니다. 사용자가 JSON을 직접 만들 필요는 없습니다.

```bash
python gates.py --root work --bind-script "/실제첨부경로/대본.txt"
```

위 명령은 원본 바이트를 `work/SOURCE_SCRIPT.txt`에 복사하고 `SCRIPT_SOURCE.json`, `body.json`을 만듭니다.
이후 body.json을 읽어 대본 분석과 컷 경계를 정합니다. 기존 body.json이 원본과 다르면 몰래 덮어쓰지 않습니다.
새 작업 폴더에 원본을 바인딩하고 분석/컷 대응부터 다시 작성합니다. 원래 대본 파일은 수정하지 않습니다.

사용자 화풍 선택, --bind-style, --plan, --cast, 청크 검증, --final은 그대로 실행합니다.
--final은 대본 원문과 화풍 원문을 모두 검사한 뒤 기존 형식의 `[대본제목]_flow.txt`를 만듭니다.
다른 경로로 작성한 최종 TXT는 다음 대본 검사도 반드시 실행합니다.

```bash
python script_integrity.py --root work --flow "work/output/대본제목_flow.txt"
```

대본 검사 결과는 `script-validation-last-run.json`에 저장됩니다. 검사 보고를 Flow 본문에 붙이지 않습니다.
원본 파일 자체의 잘림 여부와 문장 경계의 의미적 타당성을 자동으로 보증하는 도구는 아닙니다.
줄바꿈만으로 끊어진 원문 단위는 최초 대본 검토에서 확인합니다. 잘린 원본에서 뒷문장을 추측하지 않습니다.


## V2.7 최우선 — 선택한 화풍 원문을 줄이지 않습니다

1. 대본 분석 뒤 사용자에게 추천/레퍼런스/직접 화풍 중 선택받는 절차를 유지합니다. 이미 선택했으면 같은 질문을 반복하지 않습니다. 선택 전 자동 잠금은 금지합니다.
2. 선택 화풍의 `style_tail`과 `visual_spec` 다섯 항목(line_art, face_design, expression_direction, shading, palette)을 원문 그대로 사용합니다. 선·얼굴·눈·눈썹·코·입·피부·머리·표정·명암·팔레트를 짧은 태그로 바꾸지 않습니다.
3. **기본/절약형 모두 최종 프롬프트 품질 규칙이 같습니다. 절약하는 것은 반복 분석/설명이지 화풍 문장이 아닙니다.** 작품캐시에도 상세 화풍 원문 전체를 저장합니다.
4. `STYLE_TAIL_FULL`은 코드가 선택 자료에서 조립·복사합니다. 이미 완전한 원문은 글자와 구두점까지 그대로 유지합니다. 원문에 포함된 필수 세부 문장은 임의로 요약·재번역·동의어 치환하지 않습니다.
5. 모든 캐릭터 UPLOAD와 모든 영어 장면 프롬프트 끝에 동일한 원문 전체를 **한 번씩 실제로** 붙입니다. 앞부분에 한 번만 쓰기, '동일 화풍', '위와 같음', '$STYLE_TAIL', '로맨스 2D'로 대체하기, 일부 컷에서 생략하기를 금지합니다.
6. 산출물에는 사용자가 정한 `STEP 1 → UPLOAD → [대본 1~N] → ===프롬프트=== → [영어 프롬프트 1~N]`만 씁니다. `FACE DESIGN LOCK:` 같은 새 제목/라벨을 붙이지 않습니다. 상세 문장은 기존 프롬프트 한 줄의 끝부분에 자연스러운 영어 원문으로 들어갑니다.
7. 사용자 예시의 보배/한도원, 복식, 짧은 화풍 문구는 형식 예시일 뿐 다른 작품에 자동 복사하지 않습니다. 현재 선택한 레퍼런스의 화풍을 예시의 기본 2D 문구로 덮어쓰지 않습니다.
8. 전체 170단어 제한 때문에 화풍을 줄이지 않습니다. 기존 A/S/N 본문 예산은 그대로이고, 170단어 검사는 **화풍 원문을 제외한 부분**에만 적용합니다. 원문 화풍은 이 예산에서 제외합니다.
9. 프로필이 누락되거나 손상되면 일반 2D로 조용히 대체하지 않습니다. 원본을 복구하거나 구체적인 누락을 확인한 뒤 진행합니다. 새 레퍼런스 이미지의 시각 분석은 Claude가 실제 이미지를 확인해 작성하며, 이 Python 코드가 이미지를 시각적으로 분석하는 것은 아닙니다.
10. 선택한 화풍이 기본 2D로 축약되어 나온 뒤 '풀버전으로 다시 만들어 드릴까요?'라고 묻지 않습니다. **처음부터 풀버전으로 생성하고, 전달 전에 누락을 해결합니다.** 이미지 생성기의 결과가 참고 이미지와 완전히 같다고 보장하지는 않습니다.

### 내부 실행 순서 — 사용자가 JSON을 직접 만들게 하지 않습니다
Claude가 사용자 선택을 `STYLE_SELECTION.json`에 기록하고 state.json/body.json/청크를 작성합니다.

```bash
python gates.py --root work --bind-style
python gates.py --root work --plan
python gates.py --root work --cast
python gates.py --root work --final
```

`--bind-style`은 선택한 원문을 `STYLE_LOCK.json` 및 `state.json`에 복사합니다. 대본/인물/장면 설정은 바꾸지 않습니다. `--final`은 현재 선택 자료, 저장 원문, 모든 UPLOAD, 모든 장면의 원문 일치를 검사한 뒤에만 최종 TXT를 저장합니다. 내부 결과 보고는 최종 Flow TXT 안에 추가하지 않습니다.

다른 작업 경로에서 만든 완성 TXT도 다음과 같이 검사합니다.

```bash
python style_integrity.py --flow "작품_flow.txt" --lock work/STYLE_LOCK.json --selection work/STYLE_SELECTION.json --report work/style-check.json
```

화풍이 바뀌면 기존 캐시를 재사용하지 않고 사용자 선택에서 원문을 다시 바인딩합니다. 캐릭터 참조 전용 검사인 `flow_character_preflight.py`만 통과했다고 화풍 검사를 통과한 것으로 취급하지 않습니다.


## 최우선 규칙
- 최종 산출물은 사용자가 준 형식 그대로만 만든다.
- 추가 섹션, 추가 설명, 추가 태그, 추가 보고를 붙이지 않는다.
- 최종 결과 파일은 `[대본제목]_flow.txt` 한 개다.
- 최종 결과 파일 안의 순서는 반드시 아래와 같다.

```text
STEP 1

=== 영문ID (한글이름, 영문역할 / 챕터 -) ===
=== 영문ID UPLOAD ===
Single figure portrait of ...

[다음 캐릭터도 동일 반복]

[대본 1~40]
1. [대본 원문 첫 문장의 앞 30자]
2. [대본 원문 첫 문장의 앞 30자]
...
40. [대본 원문 첫 문장의 앞 30자]

===프롬프트===
[영어 프롬프트 1~40]
1. @영문ID, ... — ...
2. @영문ID, ... — ...
...
40. @영문ID, ... — ...
```

## STEP 1 캐릭터 블록 규칙
- 캐릭터마다 반드시 아래 3줄 구조만 사용한다.

```text
=== bobae (보배, peddler's daughter / 챕터 -) ===
=== bobae UPLOAD ===
Single figure portrait of a Korean Joseon-era peddler's daughter, faded indigo jeogori, hair in a low bun with binyeo, softly rounded eyes, oval face, thin arched brows, broad firm chin, straight narrow mouth, small rounded nose, small compact frame, medium shot from waist up, three-quarter left, neutral calm, plain flat neutral gray background, soft even neutral lighting, subject fully isolated, background is a plain backdrop only and not part of the character identity, no shadows on ground, no color tint, no props no other figures, [사용자가 선택한 STYLE_TAIL_FULL 원문 전체]
```

- 반드시 얼굴 묘사를 상세하게 넣는다.
- 예: eyes, face, brows, chin, mouth, nose, frame.
- 캐릭터별 UPLOAD 프롬프트에는 장면 설명을 넣지 않는다.

## [대본 1~40] 규칙
- 각 번호에는 해당 컷의 대본 원문 첫 문장의 앞 30자만 넣는다.
- 요약하거나 임의로 덧붙이지 않는다.
- 문장부호와 인용부호를 유지한다.

## [영어 프롬프트 1~40] 규칙
- 각 줄은 반드시 번호로 시작한다.
- 캐릭터 참조는 반드시 `@영문ID`를 사용한다.
- 기본 형태는 아래와 같다.

```text
1. @domanbok, faded indigo jeogori and baji, topknot with a plain headband, calm hooded eyes, oval face, solid upright frame, @bobae, faded indigo jeogori, long dark chima, hair in a low bun with binyeo, softly rounded eyes, oval face, small compact frame — Medium close-up of @domanbok and @bobae walking side by side along the lane, in crowded marketplace stalls, packed earth lane, cloth awnings, two figures, no duplicate or cloned figures, a cloth bundle carried on his back, worn sandals on the packed earth, cool daylight, reference defines face and garment identity only, pose and framing follow this description, no text no modern objects no modern buildings, natural colors, shadow areas still legible, mid-key exposure, neutral white balance, no color cast, [사용자가 선택한 STYLE_TAIL_FULL 원문 전체]
```

## 금지
- STEP 2 같은 추가 섹션 금지
- HOOK:, SAFE:, 설명문, 해설문, 요약문 추가 금지
- 캐릭터 ID 뒤에 `'s`, `’s`, 조사 붙이기 금지
- 예: `@bobae's hand` 금지 → `the hand of @bobae` 사용
- 등록되지 않은 캐릭터 ID 사용 금지

## 화풍/선택 규칙
- 대본 분석 후 화풍 추천/레퍼런스/직접 선택 절차는 유지한다.
- 그러나 최종 산출물 파일에는 선택 과정 설명을 쓰지 않는다.
- 최종 파일에는 오직 사용자가 준 형식의 산출물만 넣는다.


[V2.7.2-r2 본편 프롬프트 형식]
- [영어 프롬프트 1~N]의 각 줄은 `003 | 대본 원문 30자 | @[배경] @[인물] 실제프롬프트...` 형식을 사용합니다.
- `003 | ...`의 저장 문구는 해당 컷 대본 첫 문장의 앞 30자 그대로여야 하며 임의 요약 금지입니다.
- `@[...]` 에셋 호출은 해당 컷의 배경 set_id와 tags/subanchors와 일치해야 합니다.
- 실제 이미지 저장 파일명도 `대본원문30자.png` 기준으로 사용합니다.


[V2.7.5 이미지 저장 파일명 — 현재 프로젝트 적용 기준]
- 실제 이미지 파일명 앞에 컷 번호와 밑줄(숫자_)을 붙이지 않습니다.
- 본편은 `대본원문30자.png`, 에셋은 `영문ID.png` 또는 해당 에셋 이름으로 저장합니다.
- 예: `003_문 안에서 빗장이 밀리는 소리가 났지요.png` → `문 안에서 빗장이 밀리는 소리가 났지요.png`.
- Flow 프롬프트의 `003 | 원문30자 | @[에셋] 프롬프트` 번호와 대본 목록 번호는 순서 대응을 위해 유지합니다.
- 파일명 금지 문자는 공백으로 정리하며 이름이 겹치면 뒤에 `_중복2`, `_중복3`을 붙여 덮어쓰지 않습니다.
- image_filenames.py를 사용하고 image-filenames.json에 컷 번호와 저장 파일명 대응을 보존합니다.
- 이 규칙은 기본/절약형 모두 같으며 화풍·얼굴·캐릭터·컷 수·원문 보존 규칙은 유지합니다.
