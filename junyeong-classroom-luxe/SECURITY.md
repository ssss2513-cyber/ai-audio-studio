# 보안·권한 경계

## 회원 상태 전이

| 현재 상태 | 관리 동작 | 결과 |
|---|---|---|
| 승인 대기 | 시청 승인 / 이용 제한 / 멤버 해제 | 승인 완료 / 제한 / 해제 |
| 승인 완료 | 승인 취소 / 이용 제한 / 멤버 해제 | 승인 대기 / 제한 / 해제 |
| 이용 제한 | 제한 해제 / 멤버 해제 | 승인 대기 / 해제 |
| 멤버 해제 | 멤버 복원 / 개인정보 영구 삭제 | 승인 대기 / 삭제 |

제한·해제 상태에서 곧바로 승인을 호출하면 409로 거부합니다. 자동 승인 설정을 변경해도 기존 계정 상태는 유지됩니다. 서버의 현재 상태와 revision을 비교한 후 트랜잭션으로 변경합니다. 승인 취소·제한·해제·복원은 기존 세션을 폐기합니다. 시청 승인은 로그인된 대기 회원이 최신 상태를 확인할 수 있도록 기존 세션을 유지합니다.

## 구현된 방어

회원 DB와 영상은 web 바깥의 비공개 디스크에 저장합니다. 이름·번호는 Fernet 인증 암호화, 번호 검색키는 HMAC입니다. 비밀번호는 Argon2id 해시이며 원문 조회 API가 없습니다.

로그인 쿠키는 불투명 난수이고 서버에는 토큰 해시를 저장합니다. HttpOnly, SameSite=Lax, HTTPS 운영에서는 Secure 및 __Host- 이름을 적용합니다. 가입·로그인에는 출처 검사를 하고 인증 후 변경에는 세션별 CSRF 토큰을 확인합니다.

요청 횟수와 메타데이터·업로드 조각 크기를 제한합니다. 역할은 서버가 결정하므로 일반 가입으로 운영자가 되지 않습니다. 화면에 동적 문자열을 넣을 때 HTML 이스케이프를 적용하고, 명단 CSV의 수식 문자열에는 접두 처리를 합니다.

영상은 공개 파일 주소가 아니라 권한 검사 API를 통해 제공합니다. 재생 요청과 256 KiB 전송 블록마다 최신 세션·권한을 확인합니다. 개인정보 삭제는 멤버 해제와 별도로 이름 재입력을 요구합니다. 계정·진행 이력·세션을 삭제하고 기록 사유를 비웁니다. 처리 기록에는 내부 ID·행위·시각이 남습니다.

## 별도 운영 검토

HTTPS, 데이터 디렉터리 보호, 백업·키 보관, 패키지 보안 업데이트, 운영자 비밀번호 관리는 별도로 필요합니다. 법률 적합성을 보증하는 문서는 아닙니다.

프록시가 있다면 신뢰하는 프록시에서만 전달 헤더를 받아야 합니다. 무조건 모든 X-Forwarded-For를 신뢰하지 마세요. 공개 주소와 PUBLIC_ORIGIN이 다르면 변경 요청을 거부합니다.

한 프로세스·한 영구 디스크 방식입니다. 여러 서버의 분산 잠금·객체 저장소는 별도 구현해야 합니다. 업로드를 일반 회원에게 개방하려면 악성 파일 검사·격리된 인코딩 처리를 추가해야 합니다.

다운로드 버튼 숨김과 세션 차단은 이미 기기로 전달된 데이터를 회수하지 못합니다. 동시 접속 부하·실기기 재생·운영 환경 보안 감사는 별도입니다.
