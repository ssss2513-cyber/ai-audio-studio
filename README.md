# 🎙️ 대본 기반 화자별 자동 TTS 생성기 (Multi-Speaker Script TTS)

## v2.9.45 · 코랩 유지 + CosyVoice 2·3 캐글 GPU 2개 옵션

기존 코랩 노트북·서버·연결·기본 생성 경로는 그대로 유지합니다.
선택 범위의 모든 화자가 CosyVoice 2 또는 3이면, 3번 생성 영역에서 **캐글 GPU 2개**를 추가로 선택할 수 있습니다.
사이트에서 캐글 노트북과 대본 ZIP을 받은 뒤, Kaggle의 **GPU T4 ×2 / Internet ON**에서 ZIP을 비공개 Input으로 추가하고 실행하세요.
자세한 단계는 `Kaggle_CosyVoice_Guide.txt`에 있습니다.

- `CosyVoice2_Kaggle_DualGPU.ipynb`: 코지2 전용
- `CosyVoice3_Kaggle_DualGPU.ipynb`: 코지3 전용
- `CosyVoice2_3_Kaggle_DualGPU.ipynb`: 코지2·3 혼합 대본

물리 GPU UUID를 지정한 독립 프로세스 두 개가 각각 기존 서버·모델을 실행합니다.
각 GPU는 한 대사씩 계산하고 완료 즉시 다음 대사를 가져옵니다. 여러 대사를 묶어 전부 끝나길 기다리는 방식이 아닙니다.
혼합 대본은 코지2를 두 GPU에서 생성한 뒤 모델을 내리고, 코지3를 두 GPU에서 생성합니다.
완료 결과는 대본 순번대로 WAV로 합친 뒤 MP3를 한 번 인코딩합니다. `complete_audio.zip`에는 전체 MP3 하나와 자막을 넣습니다.
중단되면 완료 WAV와 설정을 `resume.zip`에 보관하며, 누락 대사가 있으면 최종 음성을 만들지 않습니다.

모델·소스 버전과 FP32·기존 생성 설정을 유지하며, 기존 Colab 서버 파일은 수정하지 않습니다.
설치 환경과 모델은 `/tmp`, 저장할 결과는 `/kaggle/working`에 둡니다. 캐글 기본 Python 패키지는 별도 venv로 분리합니다.
외부 서버나 터널을 만들지 않으며, 사이트의 API 키·접속 주소는 대본 ZIP에 넣지 않습니다.
노트북에는 해당 버전 코드가 포함됩니다. 코드를 바꾸면 `python build_kaggle_notebooks.py`로 다시 묶습니다.
사용자 요청에 따라 이 변경에서는 테스트·실제 GPU 실행·새 음성 생성을 하지 않았습니다. 처리 시간과 음질은 실측하지 않았습니다.

완성된 대본 속 **나레이션과 등장인물별 대사**를 자동으로 분리하여, 각 화자에게 어울리는 고품질 목소리(TTS)를 입히고 **전체 병합 오디오 및 자막(SRT/VTT)**까지 한 번에 제작해 주는 프로그램입니다.

## ✨ 주요 기능

1. **대본 자동 파싱 (화자/대사 자동 분리)**
   - `나레이션: 내용`, `[철수] 대사`, `영희: "대사"` 등 다양한 대본 형식을 완벽하게 자동 인식합니다.
   - 대본에서 등장하는 모든 인물을 중복 없이 추출하여 화자별 목록을 만듭니다.

2. **화자별 목소리 커스텀 설정**
   - 인물 및 나레이션마다 원하는 목소리(성별, 연령대, 분위기)를 자유롭게 지정할 수 있습니다.
   - 말하기 속도(속도 ±50%) 및 목소리 톤(피치 ±50Hz)을 세밀하게 조절 가능합니다.
   - 각 화자의 목소리를 즉시 들어볼 수 있는 **미리듣기(Preview)** 기능을 지원합니다.

3. **무음 간격이 조절된 전체 오디오 병합 (`full_audio.mp3`)**
   - 대사와 대사 사이의 자연스러운 호흡(무음 간격, 기본 0.5초)을 반영하여 하나의 완성된 오디오 파일로 병합합니다.

4. **영상 편집용 자막 파일 자동 생성 (`subtitles.srt`, `subtitles.vtt`)**
   - 음성 재생 길이에 맞춘 정확한 타임스탬프 기반 자막을 생성합니다. 프리미어, 파이널컷, 캡컷(CapCut), Vrew 등 영상 편집 프로그램에 바로 넣어서 작업할 수 있습니다.

5. **웹 UI (GUI) 및 CLI(명령어) 모두 지원**
   - 브라우저에서 마우스 클릭으로 직관적으로 사용하는 **웹 화면**과 대량 작업에 적합한 **터미널 명령어(CLI)**를 모두 지원합니다.

## 🚀 빠른 시작 방법

### 1. 웹 프로그램 실행 (추천)
바탕화면이나 탐색기에서 **`run_web.bat`** 파일을 더블 클릭하거나 터미널에서 다음 명령어를 실행합니다:

```bash
streamlit run app.py
```

실행하면 웹 브라우저가 자동으로 열립니다 (`http://localhost:8501`).

1. **대본 입력**: 대본을 직접 입력하거나 `.txt` 파일을 업로드한 뒤 **[화자 및 대사 분석하기]** 클릭.
2. **목소리 지정**: 감지된 화자별로 원하는 목소리를 선택하고 **[미리듣기]**로 확인.
3. **생성 및 다운로드**: **[전체 TTS 및 자막 일괄 생성 시작]** 클릭 후 완성된 오디오 재생 및 다운로드!

---

### 2. 터미널(CLI)로 일괄 실행

터미널이나 명령 프롬프트(CMD/PowerShell)에서 대본 파일을 직접 지정하여 실행할 수도 있습니다.

```bash
# 기본 실행
python main_cli.py --script sample_script.txt --output outputs/my_project

# 대사 간 무음 0.7초 설정 및 지문(괄호 속 지시문) 자동 제거 옵션
python main_cli.py --script sample_script.txt --output outputs/my_project --pause 700 --clean-stage
```

## 📝 지원하는 대본 작성 형식 예시

아래 형식들을 모두 지원하므로 편하신 방식으로 대본을 작성하시면 됩니다:

```text
나레이션: 어느 평화로운 숲속 마을에 새로운 아침이 밝아왔습니다.
민우: 오늘은 날씨가 정말 화창하네! 지수야, 우리 피크닉 갈까?
나레이션: 민우는 설레는 마음으로 가방을 챙기며 지수를 바라보았습니다.
지수: 정말 좋은 생각이야! 내가 맛있는 샌드위치를 준비해 올게.
```

- **대괄호형**: `[나레이션] ...` / `[민우] ...`
- **소괄호형**: `(나레이션) ...` / `(지수) ...`
- **따옴표형**: `민우 "오늘 날씨 좋다."`
- **지문 포함**: `지수: (웃으며) 정말 예쁘다.` (웹 화면 또는 `--clean-stage` 옵션으로 지문만 자동으로 제거하고 읽게 할 수 있습니다.)

# CosyVoice 3 별도 서버 · v2.9.42

CosyVoice 2와 3은 서로 다른 GPU 런타임·접속 주소·화자 설정으로 사용합니다.
기존 `CosyVoice_Colab_API.ipynb`와 버전 2 서버는 유지합니다.
버전 3은 `CosyVoice3_Colab_API.ipynb`에서 **1 설치 → 2 서버 준비 → 4 사이트 연결** 순서로 실행합니다.
사이트의 **CosyVoice 3 · 내 코랩 주소**에 새 주소를 넣고, 화자 카드에서 버전 3을 선택하세요.
현재 실행 중인 버전 2의 주소를 버전 3 주소로 덮어쓰지 않습니다.

버전 3에는 남성 10명·여성 10명의 VCTK 공개 참고 음성 목록이 있습니다.
기본 음성은 영어 원본 음색으로 한국어를 합성하는 교차 언어 방식입니다.
Gemini의 성우·음성이나 Qwen의 합성 샘플을 사용하지 않습니다.
**내 한국어 녹음**에서 3~30초 WAV/FLAC과 실제 녹음 대사를 등록할 수도 있습니다.
원본 음색·성별과 스타일은 별도로 선택합니다. 스타일 변경은 화자 ID를 바꾸지 않습니다.
인물의 성별이 불명확하면 카드에 확인 안내가 표시됩니다.

버전 2·버전 3·Gemini의 대기열은 독립적이며, 완료 결과는 번호순으로 MP3 하나로 합칩니다.
버전 3은 GPU 계산 한 개와 HTTP 요청 대기·파일 전송을 분리합니다.
새 모델의 GPU 동시 생성 성능이나 음질 우위를 측정한 것으로 표시하지 않습니다.
모델은 Fun-CosyVoice3-0.5B-2512 / FP32 / 공식 샘플링·생성 단계를 사용합니다.

무료 Colab에서 두 GPU 런타임을 동시에 배정받을 수 있다고 보장하지 않습니다.
외부 웹 연결이 제한되면 사이트에서 **CosyVoice 3 코랩 대본 받기**로 받은 ZIP을 코랩 3번에 올려 직접 생성합니다.
서버 감독은 실제 서버·터널 상태를 확인하는 기능으로 Colab 사용 시간 제한을 변경하지 않습니다.

참고 음성 출처: CSTR VCTK Corpus, Christophe Veaux, Junichi Yamagishi, Kirsten MacDonald,
University of Edinburgh, CC BY 4.0, https://doi.org/10.7488/ds/2645.
배포: https://huggingface.co/kyutai/tts-voices 의 `vctk/*_023.wav`.
출처와 합성 사용 표시 문구는 사이트에서 받을 수 있고 결과 ZIP에도 포함됩니다.
요청에 따라 이번 변경은 테스트·컴파일·모델 실행·실제 합성 없이 작성했습니다.
### v2.9.43 / CosyVoice 2 서버 v2.9.18

- 긴 한국어 대사를 문장 끝, 절, 띄어쓰기 순으로 분할하고 글자 누락 여부를 확인합니다. 문장 중간 분할에는 종전의 120ms 무음을 일괄 삽입하지 않습니다.
- 최대 4개 요청과 다음 대사 연속 투입을 유지합니다. 발음 계산은 겹칠 수 있지만, 공유 flow/vocoder의 변경 가능한 hook·버퍼에 동시에 접근하지 않도록 음향 계산을 잠그고 CUDA 완료까지 기다립니다.
- 정상 종료 토큰 없이 최대 토큰에 도달하거나 짧은 토큰열이 100개 이상 정확히 반복된 결과를 잘린 정상 음성으로 저장하지 않습니다. 실패 구간 재생성은 요청 전체에서 한 번까지만 합니다.
- 비제로 파형 경계의 최대 2ms만 완만하게 연결합니다. 음성 샘플을 잘라내거나 잡음 제거 필터로 대사를 지우지 않습니다.
- 모델·참고 목소리·FP32·샘플링 분포는 유지합니다. 길이·토큰 검사만으로 모든 대사 누락과 청감상 잡음을 판별할 수는 없습니다.
- 새 서버 capability가 없으면 기존 코랩 업데이트를 안내합니다. 이미 생성된 파일은 보관하며, 문제 대사만 범위 선택과 ‘완료 파일도 새로 만들기’로 재생성할 수 있습니다.
- 요청에 따라 프로젝트 테스트 및 새 TTS 합성은 실행하지 않았습니다. 실제 Colab 결과의 음질·속도는 미확인입니다.

### v2.9.44 / CosyVoice 3 코랩 v1.0.1

코랩 자식 프로세스의 stdout을 그대로 상속해 연결 주소와 설치 진행 로그가 화면에 보이지 않을 수 있는 부분을 수정했습니다. 4번 연결은 노트북 프로세스에서 직접 실행하며, 기존 런타임은 ‘서버는 정상인데 연결 주소가 안 보일 때’ 코드로 주소를 다시 표시할 수 있습니다. 모델 재설치나 새 음성 생성 없이 주소를 표시하고 실제 서버 감독을 이어갑니다.

연결 화면을 독립 모듈로 분리해, 기존 Streamlit 프로세스에 예전 화자 UI가 캐시되어 있어도 새 코랩 링크와 주소 복구 안내를 불러옵니다. 생성 작업이나 모델을 재시작하지 않습니다.

### v2.9.47 / 공유 사이트에서 캐글 생성

캐글을 사용할 때에도 공유 사이트에서 전체 생성·미리듣기를 시작하고,
완성된 MP3 한 파일과 자막을 사이트에서 재생·다운로드합니다.
왼쪽 **코지2·3 · 캐글 연결**에서 개인 API 토큰 또는 kaggle.json으로 연결한 뒤
**캐글 GPU 2개**를 선택합니다. 수동 대본 이동·노트북 실행은 필요 없습니다.

공식 Kaggle API(`kaggle==2.2.4`, Python 3.11+)가 개인 계정에 비공개 입력 데이터와
비공개 실행 작업을 만들고 `NvidiaTeslaT4`(T4 ×2)를 요청합니다.
기존 자체 포함 노트북의 설치·추론 코드를 그대로 사용합니다.
각 GPU의 독립 모델, 완료 즉시 다음 대사 배정, 전체 대본 순번 병합을 유지합니다.
새 작업마다 GPU 배정·설치·모델 준비 시간이 있으며 미리듣기도 같은 과정을 거칩니다.

작업 상태·로그·완료 개수를 사이트에서 확인하고 결과를 자동 수신합니다.
제출 응답이 모호하면 중복 제출하지 않으며, 재연결은 상태 확인과 다운로드만 합니다.
이전 작업 주소를 보관하면 새 접속에서 같은 계정으로 결과를 가져올 수 있습니다.
실패한 작업의 resume.zip이 저장됐다면 같은 대본·설정의 다음 작업에 자동 전달합니다.
새로운 대본·설정은 별도 작업입니다. 생성 중에는 작업 공간 초기화를 막습니다.

인증정보는 세션 메모리와 호출별 자식 프로세스 환경에서만 사용합니다.
