# 야담 이미지프롬프트 프로젝트 — 2.7.9 고정 작업 순서

## 1. 대본을 받으면 화풍 방식부터 질문
대본 파일을 받으면 파일 존재·읽기 가능 여부만 확인합니다. 전체 분석, 인물 확정, 프롬프트 작성, 이미지 생성보다 먼저 다음을 묻고 답을 기다립니다.

“화풍은 어떤 방식으로 정할까요?
1. 추천 화풍
2. 참조 이미지 — 원하는 그림체 이미지를 첨부해 주세요.
3. 쓰고 싶은 화풍 직접 입력”

사용자가 이번 작품의 참조 이미지나 원하는 화풍을 이미 명확히 지정했다면 그 선택을 인정하고 반복 질문하지 않습니다. ‘창조이미지’는 이 작업 흐름에서는 사용자가 주는 참조 이미지 선택으로 처리하며, 임의의 새 그림체를 자동 확정한다는 뜻으로 사용하지 않습니다.
추천을 선택하면 대본을 분석해 상세 후보를 보여주고 실제 화풍을 선택받습니다. 참조 이미지를 선택하면 실제 첨부를 보고 선·얼굴·표정·명암·팔레트를 분석합니다. 직접 입력이면 지정 내용을 상세화합니다. 추천 1위를 자동 잠금하지 않습니다.
기본/절약형 선택은 화풍 방식 질문보다 먼저 하지 않습니다. 미선택이면 화풍 방식 선택 후 기존 두 모드 중 선택받으며, 이미 선택했으면 재질문하지 않습니다.

## 2. 선택 후 대본 분석·프롬프트 작성
인물, 장소, 시간, 소품, 사건을 대본 전체에 근거해 확정하고 사용자 선택 화풍을 적용합니다. 기본 본편은 100장입니다. 사용자가 본편 수량을 명시하면 그 수량을 유지합니다.
에셋은 **인물·배경·소품 합계 정확히 18장**입니다. 인물만 18장, 인물당 18장, 18장에 배경·소품 추가가 아닙니다. 인물/배경/소품별 배분은 현재 대본에 맞춥니다. 한 작품의 배분 숫자를 다른 작품에 고정 복사하지 않습니다.
18장 목록은 실제 본편에 필요한 대상만 포함합니다. 수량을 채우려고 없는 인물·장소·소품이나 무의미한 중복을 만들지 않습니다. 대본상 필요한 18장 구성을 만들 수 없다면 구체적 충돌을 알리고, 수량이나 대본을 몰래 바꾸지 않습니다.

## 3. 인물 에셋은 한 명당 한 장의 통합 시트
한 장에 전신 정면·전신 후면 2컷과 얼굴/상반신 정면·왼쪽 45도·오른쪽 45도·측면 90도 4컷, 총 여섯 모습을 넣습니다. 여섯 독립 파일로 분리하지 않습니다. 얼굴·나이·성별·체형·머리·의상·색·장신구·화풍은 모두 같은 인물로 고정합니다.
저장명은 `영문ID_캐릭터시트.png`입니다. 이 한 장을 인물 에셋 1장으로 계산합니다. 인물 3명이면 시트 3장이며, 필요한 배경·소품까지 합쳐 전체가 18장이어야 합니다.
배경과 소품은 별도 에셋 파일로 만들고 인물 시트 안에 섞지 않습니다. 본편은 장면당 한 이미지이며 6분할 시트로 만들지 않습니다.
STEP 1의 인물 UPLOAD 프롬프트도 이제 통합 시트를 지시합니다. 단일 상반신 초상만 출력하고 시트 완료로 처리하지 않습니다.

## 4. 등록 ID·호출 ID·실제 이미지 참조 일치
대본에 근거한 에셋 레지스트리를 먼저 확정합니다. ID는 대소문자·철자·밑줄까지 동일하게 사용하고 임의 번역·별명·자동 교정으로 다른 ID를 만들지 않습니다.
`state.assets`의 18개 등록 ID, 컷별 `chapter.asset_ids`, 앞쪽 `@[ID]` 호출, 본문에 쓰는 인물 ID, 실제 참조 입력의 에셋 ID가 동일한 대상을 가리켜야 합니다. 이름만 비슷한 ID는 일치가 아닙니다. 소품 호출도 등록 대상이어야 합니다.
배경은 장소·시간대, 인물은 해당 장면에 실제 등장하는 인물, 소품은 장면에 실제 필요한 대상으로 연결합니다. 각 연결의 원문 근거와 맥락 판단을 기록합니다. `@ID's`·`@[ID]'s`처럼 ID에 소유격을 붙이지 않습니다.
없는 ID, 중복 ID, 컷과 맞지 않는 연결, 누락 참조, 다른 인물 파일, 변경된 이미지 해시가 있으면 해당 컷을 중단하고 고칩니다. 정규식 일치는 의미적 타당성이나 동일 얼굴을 보증하지 않으므로 실제 대본과 생성 이미지를 따로 검토합니다.

## 5. 프롬프트 완성 후 생성 동의
에셋 18장과 본편 프롬프트를 완성·검사한 뒤 결과를 전달하고 다음 질문을 합니다.

“에셋 이미지 생성 후 본편 이미지 만들까요?”

질문 직전 에셋 18장·본편 예정 수량을 알려줍니다. 질문을 프롬프트 본문 안에 넣지 않습니다. 이 작품의 해당 프롬프트에 대한 명확한 동의가 있기 전에는 에셋 이미지도 본편 이미지도 생성하지 않습니다. 파일 수정·규칙 수정·화풍 선택은 이미지 생성 동의가 아닙니다.
동의하면 에셋 18장을 먼저 생성하고 실제 이미지 검토를 완료한 뒤, 그 에셋을 참조해 본편을 이어서 생성합니다. 같은 동의를 반복 질문하지 않습니다. 거절/프롬프트만 요청이면 생성하지 않습니다. 대본·화풍·에셋 구성·프롬프트가 바뀌면 기존 동의를 새 계획에 자동 재사용하지 않습니다.

## 6. 생성 실행 순서
화풍 방식 선택 → 상세 화풍 확정 → 에셋 18장 및 본편 프롬프트 → ID·원문·화풍·장면검토 → 생성 동의 질문 → 동의 → 에셋 18장 생성·검수 → 본편에 실제 에셋 이미지 참조 전달 → 본편 생성·검수.
에셋 이미지 18장 모두가 실제로 준비·검토되기 전 본편을 먼저 생성하지 않습니다. `@[ID]`라는 글자만 넣는 것은 실제 참조가 아닙니다. 요청마다 해당 파일 또는 생성 도구의 유효한 이미지 식별자를 실제 reference 입력으로 전달합니다. 인물은 통합 캐릭터시트를 넣습니다.
도구 제한 때문에 필요한 참조를 빼거나 텍스트만으로 대체하지 않습니다. 생성 결과, 사용한 ID/파일/해시/이미지 식별자, 시각 검토 상태를 내부 작업 기록으로 남깁니다. 코드 검사는 선언과 파일 일치 검사이며 실제 API 전달·시각적 동일성은 실행자가 확인합니다.
이 ZIP 자체는 이미지 생성 서비스나 API 키를 제공하지 않습니다. 사용 가능한 이미지 생성 도구로 실제 실행할 때 이 순서를 지킵니다. 실행하지 않은 이미지·업로드·배포를 완료라고 보고하지 않습니다.

## 7. 그대로 유지할 규칙
- 사용자 선택 화풍의 선·얼굴·표정·명암·팔레트 원문 전체를 매 에셋/본편 프롬프트에 유지합니다. 기본/절약형 모두 동일합니다. 30자 제한은 화풍에 적용하지 않습니다.
- 본편 한 줄은 `003 | 해당 컷 원문 첫 문장의 앞 30자 | @[배경ID] @[인물ID] 실제 프롬프트` 형식입니다. 소품이 있으면 등록 소품 호출도 넣습니다. 앞부분은 원문 그대로이며 임의 요약하지 않습니다.
- 실제 본편 저장명은 원문 앞 30자를 바탕으로 하고 숫자_ 접두사는 없습니다. 파일명 금지문자·중복명은 기존 image_filenames.py 규칙을 유지합니다. 원문 매칭키는 수정하지 않습니다.
- 본편 시작 ‘옛날 옛적/옛날, 옛적’ 규칙을 유지합니다. 원본에 없으면 문장을 창작해 넣지 않습니다.
- 본편마다 서사·해설·교육적 가치 중 최소 하나를 실제 화면 표현으로 담고 불쾌감을 유발하는 연출은 보완합니다. 실제 이미지 검토 없이 합격·유튜브 승인을 보장하지 않습니다.
- 대본 근거 없는 밤·날씨·인물·사건·소품 추가 금지, 외형·체형 일관성, 기존 10종 화풍과 레퍼런스 유지.

## 8. 내부 데이터와 실행
사용자에게 JSON 작성을 시키지 않습니다. 제작 담당 AI가 작성합니다.
`state.workflow`: `style_mode`(recommended/reference/manual), `style_mode_user_message`, `style_selected_user_message`.
`state.assets`: 18개. 각 항목은 `id`, `kind`(character/background/prop), `description`, `source_evidence`, `filename`. character는 `views`에 `front_full`, `back_full`, `front_face`, `left45`, `right45`, `profile90`를 모두 기록합니다.
각 chapter의 `asset_ids`와 `asset_evidence`(ID별 현재 컷의 정확한 원문 근거)를 작성합니다. 대명사·연속 장소 등의 해석은 검토 후 기록하며, 자동 어휘 검사로 대체하지 않습니다.
`gates.py --final`이 에셋 등록/호출을 검사하고 `asset-prompts.txt`, `asset-plan.json`도 함께 생성합니다. 최종 Flow의 기존 섹션은 유지합니다.
생성 전 `workflow_guard.py --root work --stage question`으로 질문·현재 계획 해시를 준비합니다. 실제 사용자 동의 후에만 `--stage approve --user-message "실제 동의 답변"`을 실행합니다.
`--stage assets`는 동의/계획이 일치할 때만 허용합니다. 이 명령은 그림을 생성하지 않습니다.
에셋 생성 후 `ASSET_IMAGES.json`에 18개 파일의 `id`, `path`, `sha256`, `image_ref`, `review_status=APPROVED`를 기록합니다. 생성 도구가 반환한 참조 ID를 임의로 만들지 않습니다.
본편 요청 직전 `--stage scene --scene 1 --request request.json`을 실행합니다. request.json의 `asset_ids`, `image_refs`는 실제 생성 도구에 보낼 참조 목록과 같아야 합니다. 필요한 모든 파일·해시·ID·참조 순서가 일치해야 진행합니다.
