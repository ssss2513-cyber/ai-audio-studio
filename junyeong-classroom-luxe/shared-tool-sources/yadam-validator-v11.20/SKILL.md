# 야담 대본·통합 인트로 완성도 검증 스킬 V11.20 — V13.7 연동

## 고정 5막 20챕터·작법 1~2개·결말 정서 검증 — 2026-10-14

V13.7의 이번 보완판은 고정 5막, 막당 4챕터, 총 20챕터, 인트로 포함 합본 최소 35,000자를 사용한다. 60초 인트로는 본편 챕터 수에서 제외한다. 기본 대본에 막·챕터 제목이 없는 것은 정상이다. 내부 story_facts·실제 첫 문장 앵커로 20개 경계를 확인하고, 확인할 수 없으면 임의 등분하지 말고 미검증으로 남긴다.

- 먼저 고정 20개 역할·실제 사건·인과·상태 변화를 대조한다. 제목만 20개 붙였거나 한 장면을 임의로 잘라 개수를 채운 것은 역할 충족이 아니다.
- 주 작법 1개와 보조 작법 0~1개만 선택한다. 보조 없음은 정상이다. STR01~STR10 코드는 유지하고, 작법 고유의 3막·15비트·22단계를 고정 5막 20챕터 안에 대응시킨다. STR08이 주 작법일 때만 기존 15비트 위치 검사를 적용한다.
- CH10은 의미 전환이며 모든 작법의 최고 절정을 같은 곳에 강제하지 않는다. 프라이탁에서 앞선 절정 뒤 결과를 처리했다면 CH17~18에 새 절정을 요구하지 않는다.
- 기획의 main_emotion·ending_method와 CH19~20의 실제 선택·관계·결과·여운을 대조한다. 통쾌함·애틋함·신비로움 등은 작품마다 달라질 수 있다. 비극이나 신비로운 결말을 보상·출세·악인 처벌 결말로 임의 교체하지 않는다. 신비로운 여운도 중심 질문 미회수를 정당화하지 않는다.
- 다른 작품 비교 자료가 없으면 작품 간 다양성을 확인했다고 하지 않는다. 한 편에서는 정서·반전·결말의 실제 근거를 검토하고, 최근작이 제공되면 사건 원인·선택·해결·정서가 반복되는지도 확인한다. 소재 성과 조사는 추가하지 않는다.

감사 지도는 Claude가 작성한다. layout에는 format=FIVE_ACTS_20_CHAPTERS, act_count=5, chapter_count=20, chapters_per_act=4, target_chars=35000, length_scope=intro_plus_body, main_emotion, ending_method, ending_evidence_anchor를 넣는다. chapters는 20개이며 각 행에 id 1~20, act 1~5, role_id CH01~CH20, 실제 start_anchor, 그 챕터 역할을 보여 주는 role_evidence_anchor를 넣는다. role_evidence_anchor는 해당 챕터 안의 고유 원문이어야 한다. ending_evidence_anchor는 CH20 안의 실제 원문이다. 기록만으로 의미 검사를 통과시키지 않는다.

분량은 인트로 원문을 .strip()한 실측과 20개 챕터 사이 빈 줄 경계 40자를 합본 35,000자에서 빼고, 남은 수를 20개로 나눈 최소 할당량으로 확인한다. 나머지는 앞 챕터부터 1자씩 배분한다. 각 챕터 원문도 앞뒤 공백을 제거해 측정한다. 다른 챕터 초과분으로 미달을 덮지 않는다. 본편 경계가 없으면 챕터·할당량 판정은 미검증이다.

analyze_yadam.py의 fixed_layout은 개수·순서·막 배치·역할 코드·글자수·원문 근거 위치를 확인한다. 역할의 실제 의미·작법 적용·감정과 재미는 Claude가 원문을 읽어 별도로 판정한다. 코드 PASS를 완성도 자동 통과로 바꾸지 않는다. 60초·본편 대사 최대 30%·구연체·전체 대사 표시본·화자별 앞 20자·정책 구분 규칙은 현행대로 적용한다.

## V11.20 선택 강도·갈등 보존 — V13.7 연동

현재 요청에 선택 강도가 명시되면 코드에 --intensity strong 또는 --intensity existing을 전달한다. 명시가 없으면 감사 지도를 사용하며, 지도가 없으면 existing이다.

현재 요청 → 현재 작품 story_facts.intensity_mode → 기존형(existing) 순서로 선택 강도를 확인한다. 자극 강화형은 strong이다. 별도 선택 질문을 강제하거나 기존형을 임의로 강화형으로 바꾸지 않는다. script-validation-rules.md의 강도·킬포인트 의미 검토와 intro-validation-rules.md의 강화형 연결 기준을 적용한다.

정책 문제를 고칠 때 목표·잃을 것·대립 관계·선택·대가·결과를 보존한다. 허구의 배신·누명·거짓말·악인 등장이나 시청자의 분노만으로 실패시키지 않는다. 성인 해학은 선택 요소이며 누락·횟수 부족은 결함이 아니다. 큰 전환 두 개와 작은 의미 변화 네 개를 여섯 번의 정체 폭로로 강제하지 않는다.

analyze_yadam.py는 감사 지도의 선택 모드와 KP 근거 원문의 존재·고유성·제시 순서를 확인한다. 재미·인과·정책 적합성은 자동 판정하지 않는다. 자동 앵커 확인 뒤 Claude가 원문으로 의미 검토를 완료해 최종 보고서에 합친다. 구형 원고에 지도가 없으면 제공 원문에서 내부 지도를 만들며 사용자에게 JSON 작성을 요구하지 않는다. 형식 통과를 플랫폼 승인으로 표시하지 않는다.

## 교육적 가치·재미 검토 추가 — 2026-09-29

교육적 가치를 인물의 선택·대가·결과로 확인하며 재미·후킹·반전·궁금증도 별도로 검토한다. `script-validation-rules.md`의 **교육적 가치와 재미의 동시 검증** 표를 적용한다. 자동 앵커 확인만으로 의미 검증을 통과시키지 않는다. 앵커가 통과하고 의미 검토만 남으면 Claude가 해당 표를 원문 근거로 완성해 최종 판정한다. 자동 검사만 반복하며 멈추지 않는다.

## 최신 대사 비중 기준 — 2026-09-27

각 본편 챕터·인트로 제외 본편 합본의 직접 대사는 **최대 30%**다. 인트로 대화량은 자유이며 인트로 포함 합본 비율은 참고값이다. 최소 비율은 없다. 본편 30% 이하는 비율 통과, 초과는 실패로 판정한다. 문서와 `analyze_yadam.py`가 같은 범위를 검사한다. 상호 문답은 별도로 확인하되 비율 하한을 만들지 않는다. 원문을 유지해야 하는 표시·정리본 작업에서는 비중 오류를 보고만 한다.

## 최종 대본의 장 번호·장 제목 검사 — 2026-09-27

- 적용 파일은 `[제목]_대본.txt`와 `[제목]_대사.txt`다. 인트로 제작 파일의 `[INTRO SCRIPT]`, `[SCENE 1]`, IMAGE/VIDEO PROMPT와 검증보고서·설계표의 제목은 제거하지 않는다.
- `## 제6장 | 빈집의 여인`, `제6장`, `[제6장]`, `6장: 빈집의 여인`, `Chapter 6`, 제목만 있는 소제목 줄·마크다운 헤더·구분선이 낭독 원고에 있으면 수정 필요다. 장 구조는 내부 자료에만 유지한다. 장과 장 사이에는 빈 줄로만 연결한다.
- 대사 파일의 `나레이션: ## 제6장 | 빈집의 여인`도 실패다. 모든 줄에 나레이션 표시가 있다는 이유만으로 제목까지 낭독 내용으로 인정하지 않는다.
- 검증 전용은 위치와 헤더 원문을 보고한다. 제목 제거까지 요청받았거나 새 최종 원고를 만들 때에는 헤더·소제목 줄만 제외한 별도 기본 대본을 확정한 뒤, 그 확정본에서 추가 대사 파일을 다시 만든다. 나레이션·대사·쉼표·어미·사건 순서는 그대로 보존한다.
- 표시만 수정하고 기존 기본 대본을 보존하라는 요청에서는 원본을 덮어쓰지 않고 헤더 오류를 보고한다. 추가본에서만 지워 두 파일이 달라지게 만들지 않는다. 제목 제거가 승인된 수정본 기준으로 두 파일을 다시 맞춘다.
- 코드가 잡는 것은 명확한 마크다운·장 번호·구분선이다. 형식 없이 `빈집의 여인`만 있는 짧은 줄은 내부 장 제목과 문맥을 대조해 소제목인지 검수한다. 실제 이야기 문장이나 인물이 책의 `제6장`을 말하는 직접 대사는 제목으로 잘못 삭제하지 않는다.
- 제목 제거 후 순수 본문 글자 수·대사 비중을 재측정한다. 제목의 문자 수로 분량을 채우지 않는다. 검증기 코드는 읽기 전용이며 자동으로 원본을 덮어쓰지 않는다.

## V11.20 적용 범위 — V13.7 생성기와 연동

사용자의 최신 요청이 우선이다. **기본 대본은 표시 없는 낭독 원문이고, 화자 표시는 추가 대사 파일에만 붙인다.** 이름·`나레이션:`을 넣으려고 기본 대본을 고치지 않는다.

| 파일 | 검사 대상 | 화자 표시 |
|---|---|---|
| `[제목]_대본.txt` | 60초 음성 인트로부터 본편 끝까지, 분량·대사 비중·문체·인과 | 모두 없음. 직접 대사는 `"대사"` 독립 줄 |
| `[제목]_대사.txt` | 기본 대본의 모든 나레이션·대사를 같은 순서로 옮긴 추가본 | 모든 나레이션 줄에 `나레이션: `, 모든 직접 대사 줄에 실제 한글 인물명과 `: ` |
| `[제목]_화자별_대사_정리.txt` | 화자별 횟수·첫 등장 순서·발화별 원문 앞 20자 | `=== 인물명 (N회) ===` 아래 `"원문 앞 20자..."`; 나레이션 제외 |
| `[제목]_인트로_60초.txt` | 전체 음성·60초 가변 씬·상세 IMAGE/VIDEO·MASTER_01 | 제작용 영문 @태그, 실제 한국어 음성 원문은 무표시 |

### 추가 대사 파일의 필수 형식

```text
나레이션: 성복은 문 앞에 섰지요.

성복: "안에 누구 계시오?"

나레이션: 안에서는 대답 대신 빗장을 당기는 소리가 들려왔답니다.

연화: "목소리를 낮추시오. 밖에 누가 있소."
```

위 예시는 형식 설명이다. 실제 수정 때에는 문장을 새로 만들지 않고 확정된 기본 대본에서 그대로 가져온다.

- 이름 없는 대사만 뽑은 파일이 아니다. **전체 인트로의 실제 대사·필요한 나레이션, 본편 연결부, 마지막 문장까지 모든 내용**을 포함한다.
- 나레이션은 매 비어 있지 않은 원문 줄/구간 앞에 정확히 `나레이션: `을 붙인다. 처음 한 번만 붙이거나 `나래이션:`으로 적으면 실패다. 문단 안 여러 문장은 원문 그대로 유지한다.
- 직접 대사는 `성복: "대사"` 형식이다. 이름·콜론을 따옴표 안에 넣지 않는다. `화자1`, `인물A`, 영문 @태그, 시간표, 연출 설명은 넣지 않는다.
- 매 발화의 실제 인물을 직전 행동·호칭·응답과 story_facts로 확인한다. 같은 문장이 재등장해도 발화 위치마다 별도로 판단한다. 이름을 교대로 배정하지 않는다.
- **표시만 제거한 추가본과 기본 대본이 같아야 한다.** CRLF/CR과 LF의 차이만 정규화한다. 문장·어휘·어미·따옴표·문장부호·공백·빈 줄·순서·마지막 줄바꿈을 보존한다. 누락·중복·요약·문장 교체는 실패다.
- 추가본의 이름·`나레이션:`은 분량·대사 비중 계산에서 제외한다. 글자수·대사 최대 30%·구연체는 기본 대본으로만 측정한다. 정상적인 `성복: "대사"`에 기본 대본용 무표시 규칙을 적용하지 않는다.
- 대사 파일이 없으면 그 항목만 `미검증`으로 보고하고 제공된 대본 검사를 계속한다. 생성·보완까지 요청받으면 기본 대본에서 추가본을 만든다. 사용자에게 내부 지도 파일부터 만들어 달라고 요구하지 않는다.
- **표시 보완 요청의 수정 대상은 추가 대사 파일뿐이다.** 기본 대본 내용 오류를 발견해도 보고서에 기록한다. 원문을 바꿔 추가본과 일치시키지 않는다. 대본 내용 보완까지 명시적으로 요청받았을 때만 별도 기본 대본 수정본을 만들고, 그 확정본을 기준으로 추가본도 다시 검증한다. 어느 파일을 기준으로 했는지 보고한다.

### 측정과 의미 판단

기본 대본 전체를 읽고 화자 지도를 독립 작성한다. 추가본의 표시를 정답 지도에 그대로 복사하지 않는다. 내부 `speaker_map.json`에는 다음 필드를 채운다.

```json
{
  "dialogue_speakers": ["성복", "연화", "성복"],
  "allowed_speakers": ["성복", "연화"],
  "intro_speaker": "성복"
}
```

위 인명은 예시다. 첫 항목부터 마지막 항목까지 기본 대본에 있는 모든 직접 대사의 실제 화자를 순서대로 하나씩 기록한다. 지도와 표시의 일치는 기계 검사이며, **지도 자체의 정답 여부와 질문→응답·반박→재응답·선택의 의미 연결은 원문 근거로 따로 검증**한다. 화자를 확인하지 못했으면 추측해 통과시키지 말고 해당 위치만 미검증으로 남긴다.

`audit-map-template.json`을 복사한 내부 감사 지도에는 위 고정 틀의 layout·20개 chapters, 실제 `primary_structure`, 챕터의 실제 첫 문장 `start_anchor`·역할 근거 `role_evidence_anchor`, 궁금증 근거를 채운다. STR08 주 구조일 때만 beats 15개를 채운다. 다른 구조는 `beats: []`로 둔다. 원고·story_facts에 근거가 없으면 임의로 구조나 챕터 경계를 만들어 통과시키지 않는다.

```bash
python analyze_yadam.py --script "작품_대본.txt" --dialogue "작품_대사.txt" --speaker-summary "작품_화자별_대사_정리.txt" --story-title "작품" --direction "작품_인트로_60초.txt" --audit-map audit_map.json --speaker-map speaker_map.json --target 35000 --format markdown
```

`--target`은 고정 기준 35000이며 생략해도 35000을 적용한다. 다른 목표의 구형 원고를 요청 없이 이번 형식으로 재작성하지 않는다. `--script`와 `--dialogue`는 서로 다른 파일이어야 한다. 도구는 원본을 읽고 보고서만 출력한다. 파일을 직접 고치거나 TTS를 실행하지 않는다. 화자 지도는 별도 `--speaker-map` 또는 감사 지도 안 `speaker_map`으로 제공할 수 있다. 둘 다 있으면 명시적인 `--speaker-map`을 사용한다.

지도·추가본을 아직 확보하지 못한 자동 결과의 `UNVERIFIED`는 통과가 아니다. 제공된 파일 검사를 진행한 뒤 Claude가 원문에서 내부 지도를 채워 재실행한다. 도구 실행이 불가능하면 항목별로 읽고 검사하되 실제 실행·정확한 실측을 했다고 주장하지 않는다.

### 긴 나레이션의 호흡 쉼표 검사 — 2026-09-26

- 긴 나레이션을 읽고 뜻이 끊기는 경계에 쉼표 `,`가 필요한지 확인한다. 긴 시간·장소·조건절 뒤, 행동에서 반응으로 넘어가는 지점, 대비·전환 지점을 우선 검토한다.
- 쉼표가 없다는 사실이나 문장 길이만으로 실패시키지 않는다. 짧거나 한 호흡으로 자연스럽게 읽히는 문장은 그대로 둔다. 일정 글자·어절마다 자동 삽입하거나 쉼표 횟수를 할당하지 않는다.
- 이름과 조사, 관형어와 명사, 목적어와 서술어, 부정 표현과 서술어가 갈라지거나 쉼표가 과해 끊어 읽게 되는 곳도 보완한다. 원문 의미·어휘·사건·시제·정보 공개 순서는 유지한다.
- 예: `긴 복도를 지나 문 앞에 다다랐을 때 안에서 발소리가 들려왔지요.` → `긴 복도를 지나 문 앞에 다다랐을 때, 안에서 발소리가 들려왔지요.`
- 여러 사건이 과도하게 이어져 쉼표로도 읽기 어려운 문장만 자연스럽게 나눈다. 본편 문장을 나누면 종결 계열과 구연 리듬을 다시 검사한다. 인트로 나레이션은 60초 발화 계획 안에서 호흡을 다듬고 씬별 원문과 동기화한다.
- 검증 전용에서는 원문과 쉼표 제안을 보고서에 나란히 적는다. 나레이션 호흡 보완까지 요청받으면 기본 대본을 덮어쓰지 않고 별도 수정본에 최소 반영한 뒤, 그 확정본을 기준으로 추가 대사 파일도 다시 만든다. 인트로 나레이션을 고쳤으면 통합 인트로와 기본 대본 시작부도 동일하게 맞춘다.
- **기본 대본을 유지하고 추가 대사 파일의 화자 표시만 수정하라는 요청에서는, 쉼표도 기본 대본과 추가본 어느 쪽에서든 임의로 고치지 않는다.** 추가본의 표시를 제거했을 때 쉼표까지 원문과 같아야 한다. 쉼표 제안은 보고서에만 남긴다.
- 검사 코드는 직접 대사를 제외한 나레이션의 긴 문장과 가장 긴 무쉼표 구간을 검토 후보로 보여 준다. 이 수치는 낭독 시간이나 실제 호흡 실측이 아니다. Claude가 문맥을 읽고 `수정 필요 / 유지`와 그 이유를 판단한다. 자동 결과만으로 자연스러운 낭독을 보장하지 않는다.
- TTS 길이·속도·음성 모델·음성 합성은 검사 범위에 추가하지 않는다.

### V13.7과 같은 판정 기준

- **각 본편 챕터·인트로 제외 본편의 직접 대사만 30% 이하. 인트로와 최종 합본 비율은 상한 검사에서 제외.** 최소 비율은 없으며 30% 초과는 실패다. 분자와 분모 모두 공백·줄바꿈·대사를 감싼 ASCII 큰따옴표를 제외한다. `대사 문자수 × 100 ≤ 전체 문자수 × 30`으로 판단하며 반올림으로 초과분을 통과시키지 않는다.
- 각 챕터에는 다른 인물 2명 이상이 직전 발화에 응답하는 **3턴 이상 대화 교환이 최소 1개** 필요하다. 나레이션 사이에 행동·표정과 함께 배치한다. 독백·따옴표로 감싼 설명·내용 없는 맞장구로 비율을 채우지 않는다.
- 나레이션은 `~했지요·~있었지요·~였답니다·~더군요·~것이었지요`를 문맥에 맞게 섞고 `~했습니다`는 보조로 쓴다. 역사 언어의 재현을 뜻하는 것이 아니라 조선 배경 야담에 어울리는 공손한 구연체 기준이다.
- 같은 **종결 계열** 3연속은 실패다. `이었습니다→하였습니다→없었습니다`는 모두 격식형, `했지요→있었지요→것이었지요`는 모두 지요형이다. 서로 다른 동사로 바꿔 회피하지 않는다. 직접 대사를 빼고 인트로·본편·최종 합본의 나레이션을 각각 검사한다.
- Save the Cat 15비트와 위치 백분율은 **주 구조 STR08일 때만** 검사한다. 다른 주 구조와 보조 STR08에는 강제하지 않는다. 선택 구조의 기능·상태 변화·보조 작법의 실제 사건 근거는 별도로 확인한다.
- 인트로는 60초·가변 씬이며 모든 씬에서 대화를 허용한다. 모든 VIDEO 안 생성 초수와 실제 발화, 단일 MASTER_01 음악을 검사한다. 상세 기준은 intro-validation-rules.md를 따른다.
- 소재 조사·조회수와 TTS 길이·속도·음성 모델은 검증 범위에 넣지 않는다.

- 본편 글자 수·대사 비중·반말형 종결·현대식 나레이션 말끝·본편 인물 태그는 프로젝트 파일 `analyze_yadam.py`로 실측한다.
- 15비트와 궁금증 앵커는 프로젝트 파일 `audit-map-template.json`을 복사해 기록한다.

지원 파일을 읽을 수 없으면 없는 것으로 넘어가지 말고 정확한 누락 파일명을 보고한다.

## 0. 적용 범위

완성된 대본·전체 대사 파일·화자별 정리본·통합 인트로·제목·썸네일·제공된 이미지/영상의 완성도를 검사한다. 소재 조사·조회수·주제 추천 성과·외부 TTS 검사는 하지 않는다. 인트로의 현행 기준은 `intro-validation-rules.md`의 60초·가변 씬·자유 대화·연속 BGM 규격이다. 미제공 영상이나 음원을 실제 확인한 것처럼 평가하지 않는다. 기존 원고는 보존하며 수정 요청 범위에 해당하는 별도 수정본을 만든다.

## 1. 클로드 프로젝트에서 쓰는 쉬운 방법

1. 압축을 풀고 `01_클로드_프로젝트지침_복사해서넣기.txt` 내용을 프로젝트 지침란에 넣는다. `SKILL.md`와 지원 파일 5개는 같은 프로젝트 자료에 등록한다. 쉬운 설치 순서는 `00_먼저읽기_사용방법.txt`를 참고한다.
2. 검증할 기본 대본·추가 대사 파일·통합 인트로 파일을 같은 대화에 첨부한다. story_facts가 있으면 함께 첨부한다.
3. 아래처럼 한 문장만 입력한다.

`첨부한 대본과 통합 인트로를 검증하고, 오류를 고친 최종 파일까지 만들어줘.`

검증만 원하면 다음처럼 입력한다.

`첨부 파일을 검증만 해줘. 원문은 수정하지 마.`

파일이 하나뿐이어도 있는 범위부터 검증한다. 없는 파일 때문에 확인할 수 없는 항목만 `미검증`으로 표시한다.

## 2. 역할과 작업 모드

너는 칭찬 위주의 감상자가 아니라 **증거 기반 야담 검수 편집자**다.

- `분석`, `검증`, `평가`, `잘 나왔는지` → 검증 전용. 원문을 고치지 않는다.
- `수정`, `보완`, `고쳐`, `최종본`, `통과본` → 검증 후 필요한 부분만 수정한다.
- 요청이 섞이면 검증 후 수정한다.
- 사용자가 지정한 범위 밖은 함부로 다시 쓰지 않는다.
- 원본 제목, 핵심 사건, 이미 작동하는 복선과 좋은 문장은 보존한다.
- 새 인물, 새 동물, 새 소품, 새 범인, 새 능력으로 문제를 덮지 않는다.

## 3. 입력 우선순위와 파일 식별

우선순위는 다음과 같다.

`현재 사용자 요청 > 현재 첨부 원본 > 현재 첨부 생성 지침 > 이 스킬의 기본 규칙`

먼저 파일을 다음 중 하나로 분류한다.

1. 본편 대본
2. 통합 인트로: `[INTRO SCRIPT]`, 분석 데이터, 시간표, Scene 1부터 마지막 씬까지와 각 씬의 비어 있지 않은 IMAGE/VIDEO PROMPT가 한 파일에 있음
3. 구형 별도 인트로 대본·연출 파일: 입력은 허용하되 수정 산출물은 통합 인트로 한 파일로 합침
4. 대본 생성 지침
5. 설정·인물 자료
6. 제목·설명·썸네일 문구·썸네일 이미지 또는 브리프
7. 추가 대사 파일: 모든 나레이션·발화에 한글 표시를 붙인 `[제목]_대사.txt`

다른 작품이나 이전 대화의 이름·반전·소품을 섞지 않는다. 통합 인트로의 INTRO SCRIPT 전체와 기본 대본의 같은 앞부분을 먼저 대조해 경계를 찾는다. BODY OPENING 원문도 확인한다. 이 자료로도 경계가 불명확할 때만 묻는다. ‘옛날 옛적’이 없다는 이유로 중단하지 않는다.

## 4. 검증 순서

다음 순서를 바꾸지 않는다.

1. 원본 고정과 파일 분류
2. 글자 수·대사 비중·씬 수·타임코드 측정
3. 제목·대본·인트로·연출·첨부 썸네일의 YouTube 정책 위험과 시청 불쾌감 검증
4. 선택한 주 구조·보조 작법의 상태 변화 검증. 주 구조 STR08일 때만 15비트 위치 검사
5. 궁금증 Q0~Q4의 열기·단서·부분 답·최종 회수 검증
6. 시니어 구연체·종결어미·설명 나열·청취 리듬 검증
7. 사건 인과·인물 지식·호칭·대사 화자·소품 복선 및 교육적 가치·재미의 동시 검증
8. 통합 인트로의 첫 대사·장면과 본편의 사실 일치 검증
9. 같은 통합 파일 안에서 60초 가변 씬의 초반 훅·중간 재후킹·태그·음성·행동·카메라·프롬프트 검증
10. 기본 대본 무표시·추가 대사 파일 전체 표시·표시 제거 후 원문 완전 일치·실제 화자 검증 후 판정
11. 수정 요청이 있으면 치명 오류부터 최소 수정
12. 정책 검증을 포함한 같은 기준으로 최대 2회 재검증

판정은 `통과 / 조건부 통과 / 수정 필요 / 미검증` 중 하나다. 하드 게이트가 하나라도 실패하면 점수가 높아도 `통과`로 쓰지 않는다.

## 5. 본편 대본 검증

### 5-1. 길이와 대사 비중

| 고정 형식 | 합본 최소 글자 수 | 본편 챕터 |
|---|---:|---:|
| 5막·막당 4챕터 | 35,000자 이상 | 20 |

- 글자 수는 공백·문장부호·줄바꿈을 포함한 실제 원고 전체 문자 수로 측정한다. 제목·검증표·인트로 연출 프롬프트는 본편 글자 수에서 제외한다.
- 위 수치는 권장치가 아니라 **최소 하한선**이다. 90% 허용, ±10% 허용, `거의 충족` 같은 완화 판정을 쓰지 않는다.
- 이번 생성기 기준 목표는 35,000자로 고정한다. 원문이나 인트로·챕터 경계가 미확인인 항목은 미검증으로 남긴다.
- 최소 글자 수에 미달하면 `수정 필요`다. 짧은 원고로 확정할지 묻지 말고, 수정 요청이면 선택한 주 구조·반전·궁금증을 보존하면서 사건의 원인·행동·결과·감각 묘사를 확장한다.
- 최소치를 넘겼더라도 반복 문장과 의미 없는 분량 채우기가 많으면 완성도 실패로 기록한다.
- 각 본편 챕터·인트로 제외 본편 합본의 직접 대사는 **최대 30%**다. 최소 비율은 정하지 않는다.
- 분자·분모 모두 공백·줄바꿈·대사를 감싼 ASCII 큰따옴표를 제외한다. 정확한 정수 비교로 판정한다. 화자 표시가 있는 추가본은 계수에 넣지 않는다.
- 각 챕터에 실제 인물 2명 이상, 질문→응답·반박→재응답·선택으로 이어지는 최소 3턴의 대화 1회 이상을 확인한다. 나레이션은 행동·표정·증거의 변화를 이어 준다.
- 30% 초과를 고치도록 요청받았을 때만 반복 대사를 줄이고 필요한 정보를 행동·반응 나레이션으로 옮기며 핵심 문답은 유지한다. 수정 후 분량·비중·문체를 다시 검사한다. 화자 표시만 보완하는 요청에서는 기본 대본을 바꾸지 않고 초과 여부를 보고한다.

### 5-3. 궁금증 폭발

핵심 질문은 최대 3개, 보조 질문은 최대 2개다. 각 질문을 Q0~Q4로 기록한다.

| 항목 | 통과 기준 |
|---|---|
| OPEN | 누가·왜·무엇을·어떤 대가로가 분명한 구체적 모순 |
| 공정 단서 | 서로 다른 장면의 관찰 가능한 단서 최소 2개 |
| 부분 답 | 답을 주면서 목표·관계·위험·행동 중 하나를 바꿈 |
| 최종 답 | 처음 연 질문에 행동·증거·고백으로 직접 답함 |
| 후속 결과 | 답 때문에 인물의 선택이나 관계가 달라짐 |

- 늦어도 1,500자마다 새 사건·새 단서·부분 답·되돌릴 수 없는 선택 중 하나가 발생해야 한다.
- 한 장면이 연 질문은 다음 장면 첫 1~3문단에서 결과를 지불한 뒤 더 큰 질문으로 넘긴다.
- `과연 무슨 일이 벌어질까요?` 같은 빈 질문은 실패다.
- 결말에서 처음 등장한 인물·물건·능력으로 해결하면 실패다.
- 인트로가 연 핵심 질문이 본편에서 직접 닫히지 않으면 실패다.

### 5-4. 인과·인물·대사

다음을 원문 근거로 확인한다.

- 인물이 보고·듣거나 전달받지 않은 사실을 아는가
- 보지 못하는 인물이 눈빛·옷 색·표정을 직접 기억하는가
- 인물의 관계·신분·혼인·생사 상태와 호칭이 충돌하는가
- 대사 화자가 직전 행동 및 호칭과 맞는가
- 장면에 없던 인물이 자백·구출·증거 제공을 위해 갑자기 나타나는가
- 결정적 소품·치유·능력·신분 증명에 서로 다른 두 장면의 사전 단서가 있는가
- 사건의 원인과 결과, 이동 거리, 낮과 밤, 부상 상태가 이어지는가
- 시대극에 현대적인 직업어·행정어·외래어가 튀어나오는가

### 5-5. 시니어 구연체와 청취 리듬

본편 나레이션이 사람이 옆에서 들려주는 자연스러운 존댓말 구연체인지 검사한다. 문장 끝만 바꾼 가짜 구어체는 통과시키지 않는다.

- 따옴표 밖 모든 나레이션 문장을 하나씩 검사한다. `폈다.`, `다듬었다.`, `거렸다.`처럼 `습니다·입니다`가 아닌 `다.` 종결이 한 문장이라도 나오면 실패다. 문단 마지막 문장만 존댓말이어도 앞 문장을 면제하지 않는다.
- 금지 목록은 예시일 뿐 한정 목록이 아니다. 따옴표 밖 나레이션이 현대 일상 대화처럼 들리는 종결이면 목록에 없는 형태도 찾아 수정한다.
- `~했는데요·~였는데요·~었는데요·~았는데요·~는데요`, `~거든요`, `~잖아요`, `~네요`, `~죠`, `~으니까요·~니까요`, `~해요`, `~했다`뿐 아니라 아래 계열도 현대식 말끝으로 판정하고 실패 처리한다.
  - 해요체: `~아요·~어요·~여요·~예요·~이에요·~했어요·~였어요·~있어요·~없어요·~겠어요·~거예요`
  - 현대 설명·맞장구체: `~더라고요·~군요·~다고요·~라고요·~자고요·~냐고요`
  - 현대 의향·약속체: `~할게요·~하려고요·~해야 해요·~할 수 있어요`
  - 반말·친근체: `~했어·~였어·~거든·~잖아·~했지·~했네·~구나·~더라·~던데·~거야·~거지·~말이야·~같아·~싶어·~할걸·~해·~돼`
  - 비격식 `다`체: `~했다·~였다·~있었다·~없었다·~한다·~된다·~이다`를 포함한 `습니다·입니다·답니다`가 아닌 모든 문장 끝 `다.`
- 나레이션에서 허용하는 `요` 계열은 회상·흐름의 `~지요`, 실제 관찰의 `~더군요`, 궁금증을 여는 문어적 `~하였을까요·~였을까요·~것이었을까요`로 제한한다. `~인가요·~나요·~할까요`를 일상 대화처럼 쓰면 문맥에 맞는 문어적 의문형이나 평서형으로 고친다.
- 기본 나레이션은 `~했지요·~있었지요·~였답니다·~더군요·~것이었지요`를 문장 기능에 따라 섞는다. `~했습니다`는 필요한 사실 전달에 보조로 쓴다. 모든 문장을 격식형으로 바꾸지 않는다.
- 같은 종결 계열이 3문장 연속 나오면 실패다. `이었습니다·하였습니다·없었습니다`는 모두 격식형이므로 표현이 달라도 3연속이다. `했지요·있었지요·것이었지요`도 같은 지요형이다.
- 설명·이동·사실 보고만 4문장 이상 이어지고 인물 반응·감각 단서·상태 변화·다음 행동이 없으면 실패다.
- 수정 모드에서는 문맥에 따라 `~했습니다·~하였습니다`, `~되었습니다`, `~였습니다·~이었습니다`, `~있었습니다·~없었습니다`, `~였답니다`, `~했지요`, `~있었지요`, `~더군요`, `~것이었지요` 범위로 자연스럽게 고친다. 궁금증 문장은 `~하였을까요·~였을까요·~것이었을까요` 가운데 문맥에 맞는 형태를 쓴다.
- 사건·행동과 흐름은 `~했지요`, 필요한 사실의 단정은 보조적으로 `~했습니다`, 옛이야기식 설명이나 정체 공개는 `~였답니다`, 회상과 흐름 연결은 `~했지요·~있었지요`, 관찰·발견은 `~더군요`, 운명적 결과나 반전 강조는 `~것이었지요`를 우선 검토한다.
- 어미만 문자 치환하지 않는다. 앞뒤 문맥에 맞춰 조사·시제·서술어까지 자연스럽게 다듬되 사건, 인물, 횟수, 소품, 반전 사실은 바꾸지 않는다. 승인 어미도 같은 형태를 3문장 연속 반복하지 않는다.
- 큰따옴표 안 인물 대사는 자동 말끝 하드 게이트에서 제외하되, 검수자가 신분·나이·관계에 맞는 조선시대 말투인지 따로 본다. 현대식 말투가 두드러지면 `~하오·~하였소`, `~하옵니다·~이옵니다`, `~하였느냐·~하거라` 가운데 관계에 맞는 표현으로 최소 수정한다.
- 2~4문장마다 인물의 즉각 반응, 소리·촉감·빛 같은 감각, 관계의 의미 변화, 구체 행동, 새 질문 중 하나가 나타나는지 본다.
- 빈 감탄, `과연`, `그때였다`, 수사 질문을 억지로 넣어 리듬을 만든 척하면 실패다.
- 각 본편 챕터·본편 합본의 대사 비중 30% 이하와 실제 상호 대화를 유지한다. 문체 보완은 해당 나레이션의 기능에 맞게 수행한다.

검증할 때 큰따옴표 안 직접 대사를 제거한 뒤 아래와 같은 기준으로 위반 문장을 센다.

```python
import re

narration_only = re.sub(r'"[^"\n]*"|“[^”\n]*”', '', script_text)
informal_sentences = re.findall(r'[^.!?\n]+(?<!니)다(?:[.!?]|$)', narration_only)
modern_ending_pattern = re.compile(
    r'((?:했|였|었|았|던|겠)?는데요|거든요|잖아요|네요|죠|(?:으)?니까요|'
    r'더라고요|(?:라|다|자|냐)고요|(?:이)?에요|예요|거예요|인가요|'
    r'려고요|게요|(?<!더)군요|(?!(?:지|까|군)요)[가-힣]요|'
    r'거든|잖아|구나|더라|던데|는데|거야|거지|거네|말이야|'
    r'같아|싶어|할걸|[가-힣](?:어|아|지|네)|야|냐|니|해|돼|했다)'
    r'(?=[.!?]|$)'
)
```

`informal_sentences` 또는 현대식 말끝이 한 건이라도 있으면 `수정 필요`다. 수정 요청이면 잡힌 문장을 모두 문맥에 맞는 조선시대 야담 구연체로 고친 다음 같은 검사를 다시 실행한다. 두 항목 모두 0건이 되기 전에는 통과시키지 않는다.

수정할 때는 어미만 바꾸지 않는다. `원인 → 행동 → 인물·사물의 반응 → 달라진 상황 → 다음 궁금증` 가운데 빠진 기능을 보강하고 해당 문단만 고친다.

나쁜 예: `만복은 장터로 갔다. 문을 열었다. 장부를 발견했다.`

통과 예: `만복은 곧장 장터로 향했습니다. 굳게 닫힌 문을 밀자 안쪽에서 종이 스치는 소리가 났지요. 그가 틈으로 손을 넣는 순간, 감춰진 장부 한 권이 툭 떨어졌습니다.`

## 6. 60초 통합 인트로 검증

`intro-validation-rules.md`를 읽고 음성 원문·가변 씬 시간표·이미지·영상 프롬프트·MASTER_01을 함께 검증한다. 다른 씬의 발화를 일괄 금지하지 않는다. 씬당 실제 대사는 여러 인물이 주고받을 수 있고 문장 수·글자 수·대사 비율을 고정하지 않는다.

`analyze_yadam.py`가 확인하는 것은 60초 계획의 연속성, 생성 초수와 편집 구간, 발화 원문·화자·순서, @태그·복사 간격, 단일 음악 트랙의 표기 일치다. 초반 훅·재후킹의 의미, 실제 화자, 본편 근거, 음악의 청감은 자료를 읽거나 듣고 별도 판단한다.

## 7. 인트로 의미 검토

3초 훅·8초 안의 목표/손실·12~18초와 28~35초의 새로운 해석·부분 보상·선택의 대가·마지막 5초의 미해결 행동이 실제 장면에 있는지 대조한다. 모든 씬 긴장도 7 이상은 숫자만으로 인정하지 않는다. IMAGE는 시작 정지 프레임, VIDEO는 원인→행동→반응→마지막 프레임을 구체적으로 묘사해야 한다. 모든 실제 발화를 VIDEO 본문에서 확인하고 대사의 화자·시간·립싱크를 대조한다.

한 곡 MASTER_01이 0~60초 전체에 이어지며 각 씬이 독립 음악을 생성하지 않는지 확인한다. 실제 영상/음원이 없으면 `설계 확인 / 실제 재생 미검증`으로 구분한다. 문서 표기만으로 자연스러운 음악이나 60초 렌더 완료를 보장하지 않는다.

정책 참조 확인일은 2026-10-14다. 새 공식 자료를 확인했을 때만 그 실제 확인일로 갱신한다. 독창성·재사용은 https://support.google.com/youtube/answer/1311392?hl=ko, 메타데이터는 https://support.google.com/youtube/answer/2801973?hl=ko 도 참고한다.

### 8-2. 우선 검토·보완할 위험 표현

다음 내용은 묘사 강도·목적·맥락과 공식 기준을 대조한다. 채널 내부 기준상 보완해야 할 경우에도 삭제 위험·연령 제한·광고 제한 중 어느 범주인지를 구분한다.

- **성적 내용:** 노출과 신체 부위 강조, 성행위·신음·침상 행위의 상세 묘사, 관음·페티시, 성폭력·근친·비동의 접촉의 자극적 재현, 취중·수면 중 접촉을 로맨스로 포장하는 내용.
- **미성년자:** 미성년자의 혼인·연애를 성적으로 묘사하거나 성적 대상화하는 내용, 위험 행동·학대·굴욕을 충격 미끼로 반복하는 내용. 시대 배경을 예외 사유로 삼지 않는다.
- **잔혹 폭력과 동물 학대:** 피범벅, 시신·사지 훼손·참수·고문·깊은 상처의 상세 묘사, 체액과 고통을 충격 목적으로 확대하는 장면, 동물에게 위해를 가하거나 위험에 빠뜨린 뒤 구조를 연출하는 내용.
- **자살·자해:** 방법·장소·도구를 따라 할 수 있게 설명하거나 미화·도전·권유하는 내용.
- **유해·위험 행동:** 독극물·무기·방화·사기·범죄 수법을 실제로 따라 할 수 있게 단계·양·도구·회피법으로 설명하는 내용.
- **증오·괴롭힘:** 보호 대상 특성을 근거로 열등·비인간적이라고 묘사하거나 폭력·배제를 정당화하는 내용, 실제 개인을 겨냥한 위협·모욕·반복 괴롭힘.
- **오도하는 각색:** 실제 사건·실존 인물의 발언인 것처럼 꾸미거나, 가상·각색임을 알아보기 어렵게 만들어 현실 피해를 유발할 수 있는 내용.

악인의 폭력·범죄·차별이 등장한다는 사실만으로 실패시키지는 않는다. 다만 이를 미화·선동·구체적으로 가르치거나 고통 자체를 볼거리로 삼으면 실패다. 야담에서는 악행을 짧고 비노골적으로 제시하고 피해자의 선택·증거·역전·공개 심판에 중심을 둔다.

### 8-3. 이 채널의 불쾌감·시니어 친화 기준

정책 위반 여부와 별개로 다음을 제목·인트로 훅·썸네일·영상의 핵심 볼거리로 쓰면 `수정 필요`다.

- 구토물·배설물·고름·썩은 살이나 음식·구더기와 벌레 떼·노골적인 의료 처치·깊은 상처·훼손된 얼굴의 접사
- 백탁된 눈·뒤집힌 눈·상처 난 눈·기형적으로 과장된 흉터나 피부의 접사
- 장애·질병·치매·임신·출산·유산·가난·노화·외모를 괴물, 웃음거리, 응징 사유, 충격 반전으로 사용하는 표현
- `병신`, `불구`, `노망난`처럼 인물을 낮추는 비하 호칭을 제목·훅·대사에 반복하는 방식
- 장시간 구타·비명·공개 굴욕·강압·동물의 고통을 통쾌함처럼 소비하는 방식
- 실제 내용보다 성적·잔혹하게 오해하도록 만드는 낚시성 제목·썸네일

시각 장애가 있는 인물은 자연스러운 눈 모양, 시선의 초점 방식, 지팡이·손의 탐색·주변 인물의 안내처럼 존중받는 행동으로 표현한다. 눈을 하얗게 만들거나 상처를 확대해 장애를 증명하지 않는다. 임신·질병·가난은 인물의 상태일 수 있으나 무력함과 혐오를 만드는 장치로만 쓰지 않는다.

### 8-4. 제목·썸네일·인트로 연출 추가 검사

- 제목과 썸네일에 성적 신체, 피·시신·상처, 자살 방법, 아동 위험, 동물 고통을 확대하거나 충격 단어로 약속하면 실패다.
- 썸네일에 실제 대본보다 더 심한 폭력·노출·굴욕을 새로 만들어 넣으면 실패다.
- IMAGE/VIDEO PROMPT에 `close-up`, `extreme close-up`, `camera focuses on`이 신체 상처·눈의 훼손·체액·성적 부위를 향하면 실패다.
- Scene 1의 초반 훅과 첫 번째와 두 번째 재후킹은 `유혈·성적 충격·신체 혐오`가 아니라 `부당함·비밀·위험 단서·관계 역전·피할 수 없는 선택`으로 만든다.
- 실제 썸네일이나 영상이 없으면 프롬프트가 지시한 내용까지만 판정하고, 렌더 결과는 별도 `미검증`으로 적는다. 사용자가 대본·프롬프트만 검증해 달라고 했다면 실제 렌더 미첨부만으로 전체 작업을 중단하지 않는다.

### 8-5. 안전한 최소 수정 방식

- 피·상처·시신의 상세 장면 → 부러진 비녀, 찢어진 소매, 사라진 인장, 엎어진 곡식, 젖은 발자국, 비어 있는 자리
- 성적 강압·착취 → 재산 강탈, 품삯 체불, 강제 채무, 혼인 문서 위조, 누명
- 장애·질병을 이용한 충격 반전 → 생활 기술, 청각·촉각·기억·관찰, 신뢰 관계, 숨겨 둔 기록을 이용한 능동적 해결
- 동물의 고통 확대 → 비노골적인 위험 신호 뒤 즉시 구조·보호·보은 행동
- 잔혹한 응징 → 장부·증언·인장·공개 재판으로 악행이 드러나 지위·재산·신뢰를 잃는 결과

정책 위험을 고칠 때 원작의 주제와 궁금증을 지우지 않는다. 목표·잃을 것·대립 관계·선택·대가·결과를 수정 전후 대조한다. 누명·배신·악인의 거짓이 등장한다는 이유만으로 갈등 전체를 선행 이야기로 바꾸지 않는다. 같은 감정 보상을 유지하면서 사건의 표현 수단만 안전하게 바꾼다. 수정 후 제목·대본·인트로·연출 프롬프트를 다시 훑어 위험 표현이 다른 파일에 남지 않았는지 확인한다.

## 화자별 앞 20자 정리본 검사 — V11.20

- `[제목]_화자별_대사_정리.txt`는 화자별 찾기용 목록이다. `[제목]_대사.txt`의 전체 나레이션·대사 표시본과 구분한다. 전체 대본이나 전체 대사 파일을 20자로 잘라 바꾸지 않는다.
- 첫 줄 `작품 제목 — 화자별 대사 정리 (앞 20자)`, 빈 줄, `총 화자 수: N명`, 빈 줄, `=== 실제 인물명 (N회) ===` 다음에 발화별 `"원문 앞 20자..."`를 한 줄씩 둔다. 그룹 사이는 빈 줄 하나다. 이 파일의 제목·화자 헤더는 필수 서식이며 낭독 원고용 장 제목 금지에서 제외한다.
- 기본 대본의 직접 대사만 모으며 나레이션 그룹은 없다. 인트로의 모든 직접 발화도 실제 등장 횟수대로 포함한다. 그룹은 화자 첫 등장 순서, 그룹 안 발화는 원문 순서다. 같은 대사도 실제 등장한 횟수만큼 남긴다. 이름 없는 인물은 실제 역할명, 정체를 숨긴 인물은 그 시점의 표시명을 사용한다.
- 발화 1줄=1회. 총 화자 수는 실제 발화한 고유 표시명 수다. 각 화자 횟수의 합은 기본 대본의 전체 직접 발화 수와 같아야 한다.
- 바깥 따옴표·이름·콜론을 제외하고 원문 첫 문자부터 Python `text[:20]`을 사용한다. 공백·문장부호를 포함하며 내부 공백 삭제·단어 단위 조정·의미 요약·유니코드 정규화는 금지다. 원문 길이가 20자 초과일 때만 ASCII `...`를 덧붙인다. 덧붙인 말줄임표와 바깥 따옴표는 20자 계산에서 제외한다. 20자 이하는 원문 전체를 그대로 둔다.
- 실제 화자는 기본 대본·인물표에서 독립적으로 확인한다. 정리본의 이름을 정답 지도에 복사하지 않는다. 대사 속에서 부르는 상대 이름과 실제 발화자를 구분한다. 첫 20자가 같아도 서로 다른 발화를 합치지 않는다.
- 자동 검사는 `--speaker-summary`로 정리본을 받고, `--speaker-map` 또는 감사 지도 `speaker_map`과 기본 대본의 전체 발화로 예상 출력을 만들어 비교한다. 확정 작품 제목은 `--story-title` 또는 감사 지도 `story_title`로 제공한다. 내부 지도는 Claude가 작성하며 사용자에게 만들도록 요구하지 않는다.
- 누락·잘못된 인물·횟수·정렬·앞 20자·말줄임표·작품 제목 불일치는 실패다. 정리본·원문·화자 지도·확정 제목이 없어 판정할 수 없는 항목은 미검증이며 제공된 파일 검사는 계속한다. 잘린 정리본만으로 전체 대사 비중이나 생략된 내용을 검증했다고 하지 않는다.
- 정리본만 보완하라는 요청에는 정리본만 다시 만든다. 원본 대본·전체 대사 파일은 덮어쓰지 않는다. 대본 내용 보완까지 요청받아 별도 수정본을 만들었다면 최종 확정본에서 전체 대사 파일과 정리본을 다시 생성해 맞춘다.
- 검증 후 정리본 보완 파일명은 `[제목]_화자별_대사_정리_검증수정본.txt`다. 읽기 전용 검증에서는 보고서만 전달한다. 보고서에 총 화자 수·총 발화 수·화자별 횟수·앞 20자 일치·제목 일치·원본 보존을 기록한다.
- 원문 확정 후 정리본 생성은 `from analyze_yadam import build_speaker_summary`로 같은 검증기의 순수 함수를 사용할 수 있다. 함수에 원문 전체, 확정 제목, `dialogue_speakers`, `allowed_speakers`, `intro_speaker`를 넘기며 새 정리본 경로에만 저장한다. 이 함수는 화자 의미를 추론하거나 원본 파일을 수정하지 않는다.
