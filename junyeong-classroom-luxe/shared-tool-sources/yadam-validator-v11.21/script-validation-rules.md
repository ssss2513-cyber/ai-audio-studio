# 롱폼 야담 대본 검증 규칙 V11.21

## 1. 하드 게이트

- 고정 형식: 5막·막당 4챕터·총 20챕터, 인트로 포함 최소 35,000자. 선택 작법은 1~2개.
- 각 본편 챕터·인트로 제외 본편 대사 비중 최대 30%, 최소 비율 없음. 이름·나레이션 표시는 계수에서 제외.
- 선택한 주 구조와 보조 작법의 기능 충족. 주 구조 STR08일 때만 Save the Cat 15비트 순서·위치 검사.
- 인트로가 연 핵심 질문과 약속을 본편에서 회수.
- 결말의 결정적 해결책은 서로 다른 앞 장면의 단서가 2개 이상.
- 인물 지식·관계·호칭·화자·소품·시간의 치명적 모순 0건.
- 본편과 실제 음성 대사의 `@인물태그` 0건.
- 따옴표 밖 모든 나레이션 문장의 반말형 종결 0건.
- 따옴표 밖 현대식 나레이션 말끝 전 계열 0건. 아래 금지 예시는 한정 목록이 아니며, 목록에 없어도 현대 일상 대화처럼 들리면 수정한다.

하나라도 실패하면 점수가 높아도 `통과`로 판정하지 않는다.

## 2. 문장별 존댓말 검사

문단 분위기가 아니라 문장마다 검사한다. `폈다.`, `다듬었다.`, `거렸다.`, `보였다.`, `있었다.`, `한다.`처럼 `습니다·입니다`가 아닌 `다.` 종결이 한 문장이라도 있으면 실패다.

통과 예시는 `펼치기 시작하였습니다`, `다듬었습니다`, `어슬렁거리고 있었습니다`, `보였습니다`, `있었지요`다. 큰따옴표 안의 인물 직접 대사는 말투에 필요한 경우 예외로 둘 수 있지만, 따옴표 밖 나레이션은 예외가 없다.

```python
narration_only = re.sub(r'"[^"\n]*"|“[^”\n]*”', '', script_text)
informal_sentences = re.findall(r'[^.!?\n]+(?<!니)다(?:[.!?]|$)', narration_only)
```

`informal_sentences`가 1개 이상이면 `수정 필요`다. 수정 모드에서는 잡힌 문장을 모두 공손한 존댓말로 바꾸고 0건이 될 때까지 다시 검사한다.

다음 현대식 말끝도 문장마다 검사한다.

- 해요체 금지: `~아요·~어요·~여요·~예요·~이에요·~했어요·~였어요·~있어요·~없어요·~겠어요·~거예요`
- 현대 설명·맞장구체 금지: `~했는데요·~거든요·~잖아요·~네요·~죠·~으니까요·~더라고요·~군요·~다고요·~라고요·~자고요·~냐고요`
- 현대 의향·약속체 금지: `~할게요·~하려고요·~해야 해요·~할 수 있어요`
- 반말·친근체 금지: `~했어·~였어·~거든·~잖아·~했지·~했네·~구나·~더라·~던데·~거야·~거지·~말이야·~같아·~싶어·~할걸·~해·~돼`
- 비격식 `다`체 금지: `~했다·~였다·~있었다·~없었다·~한다·~된다·~이다`를 포함하여 `습니다·입니다·답니다`가 아닌 문장 끝 `다.` 전부
- 수정 후보: `~했습니다·~하였습니다`, `~되었습니다`, `~였습니다·~이었습니다`, `~있었습니다·~없었습니다`, `~였답니다`, `~했지요`, `~있었지요`, `~더군요`, `~것이었지요`
- 사건·행동의 흐름은 `~했지요`, 필요한 단정에만 보조적으로 `~했습니다`, 옛이야기식 설명·정체 공개는 `~였답니다`, 회상은 `~했지요·~있었지요`, 관찰·발견은 `~더군요`, 중요한 반전·운명적 결과는 `~것이었지요`를 먼저 검토한다.
- 나레이션의 `요` 계열은 `~지요`, 실제 관찰을 나타내는 `~더군요`, 궁금증을 여는 `~하였을까요·~였을까요·~것이었을까요`만 허용한다. 일상적인 `~인가요·~나요·~할까요`는 문어적 의문형이나 평서형으로 바꾼다.

```python
modern_ending_pattern = re.compile(
    r'((?:했|였|었|았|던|겠)?는데요|거든요|잖아요|네요|죠|(?:으)?니까요|'
    r'더라고요|(?:라|다|자|냐)고요|(?:이)?에요|예요|거예요|인가요|'
    r'려고요|게요|(?<!더)군요|(?!(?:지|까|군)요)[가-힣]요|'
    r'거든|잖아|구나|더라|던데|는데|거야|거지|거네|말이야|'
    r'같아|싶어|할걸|[가-힣](?:어|아|지|네)|야|냐|니|해|돼|했다)'
    r'(?=[.!?]|$)'
)
```

현대식 말끝이 하나라도 있으면 `수정 필요`다. 수정 모드에서는 문맥에 맞춰 조사·시제·서술어까지 자연스럽게 고치고 재검사한다. 큰따옴표 안 직접 대사는 자동 계수에서 제외하되, 신분·나이·관계에 어울리지 않는 현대 말투는 `~하오·~하였소`, `~하옵니다·~이옵니다`, `~하였느냐·~하거라` 중 알맞은 말투로 최소 수정한다.

`~했지요·~있었지요·~였답니다·~더군요·~것이었지요`를 기능에 맞게 섞고 `~했습니다`는 보조로 쓴다. `하였습니다`만 기계적으로 반복하지 않는다. 같은 종결 계열이 3문장 연속 나오면 행동 사이에 인물 반응, 감각, 관계 의미, 다음 선택을 넣어 문장 기능까지 바꾼다. 사건과 반전 사실은 바꾸지 않는다. `이었습니다·하였습니다·없었습니다`는 같은 격식형이고 `했지요·있었지요·것이었지요`는 같은 지요형이다. 직접 대사를 제외한 나레이션 순서로 검사한다.

## 3. 인물 태그 범위

- 표시 없는 기본 대본, `[INTRO SCRIPT]`, `DIALOGUE / NARRATION`의 실제 한국어 대사에는 `@태그`, 화자명, 콜론을 붙이지 않는다.
- 영문 태그는 `[CHARACTER TAG MAP]`, `CHARACTER TAGS`, `SPEAKER / LIP SYNC`, IMAGE PROMPT, VIDEO PROMPT에서만 사용한다.
- `@sooIl "이 계산판은 다릅니다."`가 본편에 있으면 실패다. 본편은 `"이 계산판은 다릅니다."`만 남긴다.

## 4. 길이와 대사 비중

| 고정 형식 | 합본 최소 글자 수 | 본편 챕터 |
|---|---:|---:|
| 5막·막당 4챕터 | 35,000자 | 20 |

- ±10%나 90% 허용을 적용하지 않는다.
- 이번 기준은 고정 35,000자다. 챕터 경계를 모르면 임의 등분하지 말고 해당 항목을 미검증으로 둔다.
- 대사 비중의 분자·분모 모두 공백·줄바꿈·ASCII 큰따옴표를 뺀다. 반올림 전 정수로 `대사 문자수 × 100 ≤ 전체 문자수 × 30`을 검사한다. 형식이 깨진 대사는 따로 실패다.
- 각 챕터에 두 인물 이상·3턴 이상의 응답이 연결되는 실제 대화 교환 1회 이상을 확인한다. 혼잣말이나 설명을 따옴표로 감싸 비중을 채우지 않는다.
- 내용 보완 요청일 때만 30% 초과 구간의 반복 대사를 덜고 필요한 정보를 행동·반응 나레이션으로 옮기며 핵심 문답을 유지한다. 표시 보완 요청에서는 기본 대본을 수정하지 않고 결과만 보고한다.
- 분량 미달은 짧은 버전으로 확정하지 않는다. 내용 확장 요청이면 선택한 주 구조와 반전을 보존하며 사건 장면을 보완한다.

## 5. Save the Cat 15비트 — 주 구조 STR08일 때만

다른 주 구조는 `NOT_APPLICABLE`이며 보조 STR08에도 아래 위치 규칙을 강제하지 않는다. 실제 선택 구조의 기능과 상태 변화는 원문으로 검증한다.

각 비트는 이름이 아니라 사건 전후의 상태 변화로 인정한다.

1. 오프닝 이미지: 주인공의 결핍·불균형
2. 주제 제시: 결말에서 증명될 가치나 질문
3. 설정: 일상·관계·약점과 갈등 재료
4. 기폭제: 기존 삶을 되돌릴 수 없게 흔드는 사건
5. 고민: 행동할지 피할지의 실제 선택 압박
6. 2막 진입: 새로운 규칙의 세계로 들어가는 능동적 선택
7. B 스토리: 관계·감정·주제의 열쇠
8. 재미와 놀이: 제목이 약속한 상황의 서로 다른 변주
9. 중반점: 부분 진실 또는 거짓 승패로 목표·위험 변화
10. 악당이 다가오다: 외부 적과 내부 약점의 동시 압박
11. 모든 것을 잃다: 가치·관계·증거·지위의 실제 손실
12. 영혼의 어두운 밤: 실패 원인과 주제의 재해석
13. 3막 진입: A 단서와 B 감정 열쇠를 결합한 새 계획
14. 피날레: 변화된 행동으로 반격과 결말 완성
15. 파이널 이미지: 오프닝 이미지의 시각적 반전

핵심 위치는 기폭제 8~12%, 2막 진입 18~22%, 중반점 47~53%, 모든 것을 잃다 68~75%, 3막 진입 78~83%, 피날레 80% 이후다. 60초 인트로는 위치 계산에서 제외한다.

## 6. 궁금증과 인과

- Q0~Q4별 OPEN 앵커, 서로 다른 단서 2개 이상, 부분 답, 최종 답을 기록한다.
- 이미 닫힌 질문을 다시 미끼로 쓰지 않는다.
- 인트로에서 `팔렸다`고 했는데 본편에서 `사라졌다`고 바꾸는 약속 변형을 금지한다.
- 지식 지도, 행동 지도, 관계 지도, 소품·능력 지도를 작성한다.
- 보지 못한 것을 봤다고 말하거나, 장면에 없던 인물이 해결을 위해 갑자기 나타나면 실패다.

## 7. 반복과 청취 리듬

- 설명·이동·사실 보고만 4문장 이상 이어지면 실패다.
- 2~4문장마다 인물 반응·감각 단서·관계 변화·구체 행동·새 질문 중 하나가 있어야 한다.
- 일반 구간은 1,500자 안에 새 사건·단서·부분 답·되돌릴 수 없는 선택이 나타나야 한다.
- 장면 끝 갈고리는 다음 장면 첫 1~3문단에서 직접 결과를 보여준 뒤 더 큰 질문으로 넘긴다.
- 빈 감탄, `과연`, `그때였다`, 억지 수사 질문으로 리듬을 만든 척하지 않는다.

### 긴 나레이션의 호흡 쉼표 검사 — 2026-09-26

- 긴 나레이션을 읽고 뜻이 끊기는 경계에 쉼표 `,`가 필요한지 확인한다. 긴 시간·장소·조건절 뒤, 행동에서 반응으로 넘어가는 지점, 대비·전환 지점을 우선 검토한다.
- 쉼표가 없다는 사실이나 문장 길이만으로 실패시키지 않는다. 짧거나 한 호흡으로 자연스럽게 읽히는 문장은 그대로 둔다. 일정 글자·어절마다 자동 삽입하거나 쉼표 횟수를 할당하지 않는다.
- 이름과 조사, 관형어와 명사, 목적어와 서술어, 부정 표현과 서술어가 갈라지거나 쉼표가 과해 끊어 읽게 되는 곳도 보완한다. 원문 의미·어휘·사건·시제·정보 공개 순서는 유지한다.
- 예: `긴 복도를 지나 문 앞에 다다랐을 때 안에서 발소리가 들려왔지요.` → `긴 복도를 지나 문 앞에 다다랐을 때, 안에서 발소리가 들려왔지요.`
- 여러 사건이 과도하게 이어져 쉼표로도 읽기 어려운 문장만 자연스럽게 나눈다. 본편 문장을 나누면 종결 계열과 구연 리듬을 다시 검사한다. 인트로 나레이션은 60초 발화 계획 안에서 호흡을 다듬고 씬별 원문과 동기화한다.
- 검증 전용에서는 원문과 쉼표 제안을 보고서에 나란히 적는다. 나레이션 호흡 보완까지 요청받으면 기본 대본을 덮어쓰지 않고 별도 수정본에 최소 반영한 뒤, 그 확정본을 기준으로 추가 대사 파일도 다시 만든다. 인트로 나레이션을 고쳤으면 통합 인트로와 기본 대본 시작부도 동일하게 맞춘다.
- **기본 대본을 유지하고 추가 대사 파일의 화자 표시만 수정하라는 요청에서는, 쉼표도 기본 대본과 추가본 어느 쪽에서든 임의로 고치지 않는다.** 추가본의 표시를 제거했을 때 쉼표까지 원문과 같아야 한다. 쉼표 제안은 보고서에만 남긴다.
- 검사 코드는 직접 대사를 제외한 나레이션의 긴 문장과 가장 긴 무쉼표 구간을 검토 후보로 보여 준다. 이 수치는 낭독 시간이나 실제 호흡 실측이 아니다. Claude가 문맥을 읽고 `수정 필요 / 유지`와 그 이유를 판단한다. 자동 결과만으로 자연스러운 낭독을 보장하지 않는다.
- TTS 길이·속도·음성 모델·음성 합성은 검사 범위에 추가하지 않는다.

## 8. 수정 순서

1. 반말형 나레이션과 본편 인물 태그를 모두 제거한다.
2. 내용 보완 요청의 범위 안에서 최소 글자 수·대사 30% 이하·상호 대화를 맞춘다.
3. 미회수 도입 약속을 회수하거나 삭제한다.
4. 주 구조 STR08일 때 중반점과 모든 것을 잃다를 분리한다. 다른 구조는 자체 기능을 검증한다.
5. 선택 구조의 전환·압박·실제 대가가 사건에서 생기는지 확인한다.
6. 선택 구조의 해결과 결과에서 주인공의 능동적 선택을 보강한다.
7. 인물 지식·호칭·화자·관계·소품 모순을 고친다.
8. 같은 기준으로 재검증한다.

## 9. 추가 대사 파일은 별도 검사


```text
나레이션: 성복은 문 앞에 섰지요.

성복: "안에 누구 계시오?"

나레이션: 안에서는 대답 대신 빗장을 당기는 소리가 들려왔답니다.

연화: "목소리를 낮추시오. 밖에 누가 있소."
```

위 예시는 형식 설명이다. 실제 수정 때에는 문장을 새로 만들지 않고 확정된 기본 대본에서 그대로 가져온다.

- 이름 없는 대사만 뽑은 파일이 아니다. **전체 인트로의 실제 대사·필요한 나레이션, 본편 연결부, 마지막 문장까지 모든 내용**을 포함한다.
- 나레이션은 매 비어 있지 않은 원문 줄/구간 앞에 정확히 `나레이션: `을 붙인다. 처음 한 번만 붙이거나 `나래이션:`으로 적으면 실패다. 문단 안 여러 문장은 원문 그대로 유지한다.
- 직접 대사는 `성복: "대사"` 형식이다. 이름·콜론을 따옴표 안에 넣지 않는다. `화자1`, `인물A`, 영문 @태그, 시간표, 연출 설명은 넣지 않는다.
- 매 발화의 실제 인물을 직전 행동·호칭·응답과 story_facts로 확인한다. 같은 문장이 재등장해도 발화 위치마다 별도로 판단한다. 이름을 교대로 배정하지 않는다.
- **표시만 제거한 추가본과 기본 대본이 같아야 한다.** CRLF/CR과 LF의 차이만 정규화한다. 문장·어휘·어미·따옴표·문장부호·공백·빈 줄·순서·마지막 줄바꿈을 보존한다. 누락·중복·요약·문장 교체는 실패다.
- 추가본의 이름·`나레이션:`은 분량·대사 비중 계산에서 제외한다. 글자수·대사 최대 30%·구연체는 기본 대본으로만 측정한다. 정상적인 `성복: "대사"`에 기본 대본용 무표시 규칙을 적용하지 않는다.
- 대사 파일이 없으면 그 항목만 `미검증`으로 보고하고 제공된 대본 검사를 계속한다. 생성·보완까지 요청받으면 기본 대본에서 추가본을 만든다. 사용자에게 내부 지도 파일부터 만들어 달라고 요구하지 않는다.
- **표시 보완 요청의 수정 대상은 추가 대사 파일뿐이다.** 기본 대본 내용 오류를 발견해도 보고서에 기록한다. 원문을 바꿔 추가본과 일치시키지 않는다. 대본 내용 보완까지 명시적으로 요청받았을 때만 별도 기본 대본 수정본을 만들고, 그 확정본을 기준으로 추가본도 다시 검증한다. 어느 파일을 기준으로 했는지 보고한다.


검사 실행·화자 지도·챕터 앵커 형식은 SKILL.md의 V11.21 적용 범위를 따른다. 대사 파일 누락은 그 항목의 미검증이며, 기본 대본의 표시 없음은 정상이다. 실제 화자 오류는 문맥으로 검증한다.

## 최종 대본의 장 번호·장 제목 검사 — 2026-09-27

- 적용 파일은 `[제목]_대본.txt`와 `[제목]_대사.txt`다. 인트로 제작 파일의 `[INTRO SCRIPT]`, `[SCENE 1]`, IMAGE/VIDEO PROMPT와 검증보고서·설계표의 제목은 제거하지 않는다.
- `## 제6장 | 빈집의 여인`, `제6장`, `[제6장]`, `6장: 빈집의 여인`, `Chapter 6`, 제목만 있는 소제목 줄·마크다운 헤더·구분선이 낭독 원고에 있으면 수정 필요다. 장 구조는 내부 자료에만 유지한다. 장과 장 사이에는 빈 줄로만 연결한다.
- 대사 파일의 `나레이션: ## 제6장 | 빈집의 여인`도 실패다. 모든 줄에 나레이션 표시가 있다는 이유만으로 제목까지 낭독 내용으로 인정하지 않는다.
- 검증 전용은 위치와 헤더 원문을 보고한다. 제목 제거까지 요청받았거나 새 최종 원고를 만들 때에는 헤더·소제목 줄만 제외한 별도 기본 대본을 확정한 뒤, 그 확정본에서 추가 대사 파일을 다시 만든다. 나레이션·대사·쉼표·어미·사건 순서는 그대로 보존한다.
- 표시만 수정하고 기존 기본 대본을 보존하라는 요청에서는 원본을 덮어쓰지 않고 헤더 오류를 보고한다. 추가본에서만 지워 두 파일이 달라지게 만들지 않는다. 제목 제거가 승인된 수정본 기준으로 두 파일을 다시 맞춘다.
- 코드가 잡는 것은 명확한 마크다운·장 번호·구분선이다. 형식 없이 `빈집의 여인`만 있는 짧은 줄은 내부 장 제목과 문맥을 대조해 소제목인지 검수한다. 실제 이야기 문장이나 인물이 책의 `제6장`을 말하는 직접 대사는 제목으로 잘못 삭제하지 않는다.
- 제목 제거 후 순수 본문 글자 수·대사 비중을 재측정한다. 제목의 문자 수로 분량을 채우지 않는다. 검증기 코드는 읽기 전용이며 자동으로 원본을 덮어쓰지 않는다.


## 화자별 앞 20자 정리본 검사 — V11.21

- `[제목]_화자별_대사_정리.txt`는 화자별 찾기용 목록이다. `[제목]_대사.txt`의 전체 나레이션·대사 표시본과 구분한다. 전체 대본이나 전체 대사 파일을 20자로 잘라 바꾸지 않는다.
- 첫 줄 `작품 제목 — 화자별 대사 정리 (앞 20자)`, 빈 줄, `총 화자 수: N명`, 빈 줄, `=== 실제 인물명 (N회) ===` 다음에 발화별 `"원문 앞 20자..."`를 한 줄씩 둔다. 그룹 사이는 빈 줄 하나다. 이 파일의 제목·화자 헤더는 필수 서식이며 낭독 원고용 장 제목 금지에서 제외한다.
- 기본 대본의 직접 대사만 모으며 나레이션 그룹은 없다. 인트로의 모든 직접 발화도 실제 등장 횟수대로 포함한다. 그룹은 화자 첫 등장 순서, 그룹 안 발화는 원문 순서다. 같은 대사도 실제 등장한 횟수만큼 남긴다. 이름 없는 인물은 실제 역할명, 정체를 숨긴 인물은 그 시점의 표시명을 사용한다.
- 발화 1줄=1회. 총 화자 수는 실제 발화한 고유 표시명 수다. 각 화자 횟수의 합은 기본 대본의 전체 직접 발화 수와 같아야 한다.
- 바깥 따옴표·이름·콜론을 제외하고 원문 첫 문자부터 Python `text[:20]`을 사용한다. 공백·문장부호를 포함하며 내부 공백 삭제·단어 단위 조정·의미 요약·유니코드 정규화는 금지다. 원문 길이가 20자 초과일 때만 ASCII `...`를 덧붙인다. 덧붙인 말줄임표와 바깥 따옴표는 20자 계산에서 제외한다. 20자 이하는 원문 전체를 그대로 둔다.
- 실제 화자는 기본 대본·인물표에서 독립적으로 확인한다. 정리본의 이름을 정답 지도에 복사하지 않는다. 대사 속에서 부르는 상대 이름과 실제 발화자를 구분한다. 첫 20자가 같아도 서로 다른 발화를 합치지 않는다.
- 자동 검사는 `--speaker-summary`로 정리본을 받고, `--speaker-map` 또는 감사 지도 `speaker_map`과 기본 대본의 전체 발화로 예상 출력을 만들어 비교한다. 확정 작품 제목은 `--story-title` 또는 감사 지도 `story_title`로 제공한다. 내부 지도는 Claude가 작성하며 사용자에게 만들도록 요구하지 않는다.
- 누락·잘못된 인물·횟수·정렬·앞 20자·말줄임표·작품 제목 불일치는 실패다. 정리본·원문·화자 지도·확정 제목이 없어 판정할 수 없는 항목은 미검증이며 제공된 파일 검사는 계속한다. 잘린 정리본만으로 전체 대사 비중이나 생략된 내용을 검증했다고 하지 않는다.
- 정리본만 보완하라는 요청에는 정리본만 다시 만든다. 원본 대본·전체 대사 파일은 덮어쓰지 않는다. 대본 내용 보완까지 요청받아 별도 수정본을 만들었다면 최종 확정본에서 전체 대사 파일과 정리본을 다시 생성해 맞춘다.
- 검증 후 정리본 보완 파일명은 `[제목]_화자별_대사_정리_검증수정본.txt`다. 읽기 전용 검증에서는 보고서만 전달한다. 보고서에 총 화자 수·총 발화 수·화자별 횟수·앞 20자 일치·제목 일치·원본 보존을 기록한다.
- 원문 확정 후 정리본 생성은 `from analyze_yadam import build_speaker_summary`로 같은 검증기의 순수 함수를 사용할 수 있다. 함수에 원문 전체, 확정 제목, `dialogue_speakers`, `allowed_speakers`, `intro_speaker`를 넘기며 새 정리본 경로에만 저장한다. 이 함수는 화자 의미를 추론하거나 원본 파일을 수정하지 않는다.


## 교육적 가치와 재미의 동시 검증 — V11.21

교육적 가치와 이야기의 재미를 각각 확인한다. 좋은 교훈이 있다는 이유로 약한 후킹·설교·뻔한 결말·설명 반복을 통과시키지 않는다. 한 작품의 핵심 배움은 1개, 필요한 보조 배움은 1개까지다. 장르를 모두 권선징악으로 바꾸거나 행복한 결말을 강제하지 않는다.

| 항목 | 원문에서 확인할 근거 | 보완이 필요한 경우 |
|---|---|---|
| 구체적 배움 | 생활·관계·판단에 연결되는 이 작품만의 뜻 | 착하게 살자는 문구만 있고 사건과 무관함 |
| 선택과 결과 | 대가가 있는 선택, 그로 인해 달라진 사건·관계 | 우연한 상이나 벌로 교훈을 대신함 |
| 마지막 회수 | 초반 문제와 이어지는 마지막 행동·관계·비극의 결과 | 마지막에 조언만 새로 붙임 |
| 재미·몰입 | 교육 장면의 새 단서·실패·대가·관계 변화, 남은 궁금증 | 변화 없이 훈계만 하거나 정답을 미리 알려 반전을 망침 |
| 자연스러운 구연 | 행동 중심, 필요한 경우 여운 속 1~2문장 이내 정리 | 같은 교훈 반복·장광설·시청자에게 무조건적인 복종이나 희생 강요 |
| 정보의 정확성 | 사실로 소개하는 문화·역사 정보의 확인 근거 | 창작·설화·근거 없는 효험을 검증된 사실처럼 전달 |

- 각 항목을 `통과 / 수정 필요 / 미검증 / 해당 없음`으로 판정하고 원문 위치·짧은 인용·이유를 기록한다. 사실 정보가 없는 경우에만 정보 확인을 해당 없음으로 둘 수 있다. 실제 교육적 가치·재미 검토 없이 전체 통과로 표시하지 않는다.
- 교육 장면을 읽고 `이 장면에서 사건이나 관계가 무엇이 달라졌는가`, `다음 일을 궁금하게 하는가`, `교훈의 정답을 먼저 말해 반전을 약화시키지 않았는가`를 답한다. 숫자 점수나 키워드 횟수로 재미가 검증되었다고 하지 않는다.
- `교훈·교육·정직`이라는 단어가 없다는 이유로 실패시키지 않는다. 행동으로 뜻이 전달되면 별도 교훈 문장은 없어도 된다. 교훈을 말하는 대사가 있어도 실제 인과가 없으면 미충족이다. 비극·회상 구조·끝까지 신념을 지킨 인물도 원문의 인과와 결과로 판단한다.
- 감사 지도 `educational_value`에 `learning_focus`, `choice_anchor`, `consequence_anchor`, `payoff_anchor`를 채운다. 앵커는 본편에서 한 번 등장하는 실제 원문이며 각 역할을 구별한다. story_facts에 없으면 Claude가 원문을 읽고 내부 작성한다. 사용자에게 별도 교육 파일을 요구하지 않는다.
- `analyze_yadam.py`는 앵커 존재·고유성·겹침만 검사한다. `evidence_status: PASS`는 위치 확인이며 교육성과 재미의 통과가 아니다. `semantic_status: UNVERIFIED`는 정상적인 의미 검토 대기 표시다. Claude가 위 표의 원문 근거와 판단을 보고서에 추가한 뒤 최종 판정한다. 자동 결과를 PASS로 바꾸기 위해 원문이나 지도에 가짜 근거를 쓰지 않는다.
- `evidence_status: PASS`이고 의미 검토만 남았다면 자동 검사를 반복하거나 사용자에게 계속 여부를 묻지 않는다. Claude가 위 표를 실제로 검토해 보고서에 근거와 최종 판정을 작성한다. 자동 측정의 `UNVERIFIED`는 그대로 보존하고, 의미 검토까지 충족한 최종 판정과 구분해 보고한다. 이 단계에 새 파일·승인·자동 검사 재실행을 요구하지 않는다.
- 지도 누락·오기·잘못된 앵커는 지도를 고칠 사유이며 그 자체가 원고의 교육성이 없다는 뜻은 아니다. 도구 실행·출처 확인이 불가능하면 해당 항목만 미검증으로 남긴다.
- 보완 요청 범위에서만 수정한다. 교육적 가치를 넣으라는 요청은 선택·결과를 잇는 해당 장면을 최소한으로 보완할 수 있으나 새 주인공·사건의 결말·확정 반전을 임의로 갈아엎지 않는다. 기존 원고는 덮어쓰지 않고 별도 수정본을 만든다. 표시·정리본만 수정하는 요청에는 원고를 바꾸지 않는다.
- 수정 후 대사 최대 30%·최소 글자수·구연체·원문과 인트로 일치·후킹·궁금증 회수를 다시 확인한다. 확정 기본 대본에서 전체 대사 파일과 화자별 앞 20자 정리본을 다시 맞춘다. 낭독 원고에 `교육적 가치`나 장 제목을 붙이지 않는다.
- 교육적 가치 자료는 기존 story_facts·감사 지도·검증보고서에 포함한다. 독립 교훈 파일은 추가하지 않으며 생성기 최종 산출물 6종과 검증기 프로젝트 파일 6개를 유지한다.

## 선택 강도·두 킬포인트·갈등 보존 — V11.21

- 모드는 현재 요청 → 작품 기록 → 기존형(existing) 순서다. 자극 강화형(strong)을 원할 때만 압박과 역전을 강화한다.
- 강화형의 압박 수단 2~3개, 잃을 것, KP1·KP2, 선택·대가·결과를 원문으로 확인한다. 기존형은 이미 설계된 큰 전환만 검사하며 불필요한 배신·폭로나 새 절정을 만들지 않는다.
- T1~T6은 큰 전환 2개+작은 의미 변화 4개로 충족할 수 있다. 작은 변화도 목표·관계·해석·행동을 바꿔야 한다. 여섯 정체 폭로나 같은 위기의 반복은 보완한다.
- 각 킬포인트의 직전 예상, 서로 다른 장면의 공정 단서 두 개, 실제 반전 행동, 선택·대가, 뒤따르는 결과를 읽는다. 앵커 순서만으로 공정한 복선·재미까지 통과시키지 않는다.
- 성인 해학은 선택 요소다. 횟수·성적 뉘앙스 부족은 결함이 아니다. 강화형도 성적·잔혹한 묘사를 더하는 모드가 아니다.
- 악인의 배신·거짓·누명이나 시청자의 분노 자체는 자동 실패 사유가 아니다. 정책과 채널 내부 기준을 구분하고 문제가 되는 표현 수단만 고친다.
- 수정 전후 목표·손실·대립 관계·선택·대가·결과·감정 보상을 대조한다. 위험 묘사를 순화하며 장면의 이유와 재미까지 사라졌다면 보완한다.
- 압박 뒤 짧은 반응·관계·재치의 호흡을 허용한다. 모든 문장을 고함·위협으로 바꾸지 않는다.

감사 지도에 intensity.mode, selection_source, pressure_mechanism, loss_at_stake, kill_points를 기록한다. 각 KP는 id, clue_anchors 두 개, turn_anchor, consequence_anchor를 실제 본편의 고유 원문으로 채운다. 같은 문장이 반복되면 더 긴 고유 문맥을 사용한다. 강화형은 KP1·KP2 필수다. 기존형에 지도 자료가 없다고 내용 결함으로 단정하지 않는다.

감사 지도는 Claude가 작성한다. layout에는 format=FIVE_ACTS_20_CHAPTERS, act_count=5, chapter_count=20, chapters_per_act=4, target_chars=35000, length_scope=intro_plus_body, main_emotion, ending_method, ending_evidence_anchor를 넣는다. chapters는 20개이며 각 행에 id 1~20, act 1~5, role_id CH01~CH20, 실제 start_anchor, 그 챕터 역할을 보여 주는 role_evidence_anchor를 넣는다. role_evidence_anchor는 해당 챕터 안의 고유 원문이어야 한다. ending_evidence_anchor는 CH20 안의 실제 원문이다. 기록만으로 의미 검사를 통과시키지 않는다.

분량은 인트로 원문을 .strip()한 실측과 20개 챕터 사이 빈 줄 경계 40자를 합본 35,000자에서 빼고, 남은 수를 20개로 나눈 최소 할당량으로 확인한다. 나머지는 앞 챕터부터 1자씩 배분한다. 각 챕터 원문도 앞뒤 공백을 제거해 측정한다. 다른 챕터 초과분으로 미달을 덮지 않는다. 본편 경계가 없으면 챕터·할당량 판정은 미검증이다.

analyze_yadam.py의 fixed_layout은 개수·순서·막 배치·역할 코드·글자수·원문 근거 위치를 확인한다. 역할의 실제 의미·작법 적용·감정과 재미는 Claude가 원문을 읽어 별도로 판정한다. 코드 PASS를 완성도 자동 통과로 바꾸지 않는다. 60초·본편 대사 최대 30%·구연체·전체 대사 표시본·화자별 앞 20자·정책 구분 규칙은 현행대로 적용한다.
