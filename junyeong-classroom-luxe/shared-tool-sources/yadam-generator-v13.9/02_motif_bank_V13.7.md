- **찾아 읽기:** 선택 장르/HIT와 관련된 분류를 정한 뒤 태그·갈등·해결 기능으로 검색한다. 01~20, 21~40, 41~60, 61~80의 네 구간 중 세 구간 이상에서 총 8~12개 후보를 확보하고, 후보 행만 자세히 읽는다. 01~04만 반복하거나 파일 전체를 매번 출력·재독하지 않는다. 특정 모티프를 지정한 요청에는 해당 항목을 바로 사용한다.
- **반복 회피:** 아래 최근 7일 기록과 대조해 사용한 핵심 모티프를 빼고, A~D는 서로 다른 핵심 태그·해결 방식으로 만든다. 적합한 후보가 부족할 때만 검색 범위를 넓힌다. 순번을 기계적으로 돌리는 방식은 쓰지 않는다.
- **재미와 배움:** 각 추가 항목은 `사건·갈등·전환 → 선택·해결`을 갖춘 씨앗이다. 집필에서는 첫 모순, 능동적 시도, 실패의 대가, 의미가 바뀌는 단서를 구체화한다. V 코드는 설계용이며 교훈을 미리 설명하거나 본문 표제로 출력하지 않는다.
- **확인 범위:** 판타지 동물의 의도·능력은 창작 설정이다. 실제 생태·의술·역사 지식으로 단정하지 않는다. H 분류의 추가 항목도 역사풍 창작이며 실존 인물의 실제 일화라고 주장하지 않는다. 구체적인 제도·연도·실존 인물을 사실로 소개할 때만 별도로 확인한다.

### 3-1. 적용 하드 룰

1. 기본 4안은 서로 다른 HIT 코드 네 가지를 주 소재로 쓴다. 사용자가 특정 HIT 소재를 지정한 때만 같은 코드 안에서 사건 엔진이 다른 4안을 만든다.
2. 주 소재 1개는 제목·인트로·발단 연결·서로 다른 시도 3회·의미 전환·최종 보상를 관통한다. 보조 소재는 원인·조력·증거 중 하나만 강화한다.
3. 최근 완성작 최대 5편과 `HIT 코드 + 핵심 모티프 + 해결 엔진 + 결말 코드`가 같으면 폐기한다.
4. 인기작의 제목 문장, 장면 순서, 반전 공개 순서, 결말을 복사하지 않고 이야기 지문 7칸 중 최소 4칸을 바꾼다.
5. HIT 코드만 적고 본문에 기대 장면이 없으면 실패다. 선택 구조의 실제 사건 E에서 주 소재의 재미를 서로 다른 방식으로 최소 3회 변주한다.

## 4. 핵심 모티프 640종

### 5-7. 해결 방식 분산 하드 룰

주제 4안은 결말 문구만 바꾸지 말고 **해결 엔진 자체를 최소 4종으로 분산**한다. 아래 16종 중 같은 주 해결 엔진은 한 번만 쓴다. 소재에 맞지 않는 방식을 억지로 섞지 말고 후보를 다시 고른다.

1. `S1 공개 증거·재심` — 두 개 이상의 공정 단서로 판결을 뒤집는다.
2. `S2 제한 시간 구조` — 위험이 닥치기 전에 사람·마을·생업을 구한다.
3. `S3 자발적 선택` — 혼인·이별·귀향·동업을 당사자가 직접 결정한다.
4. `S4 관계 책임` — 사과만 하지 않고 빚·돌봄·상속의 책임을 재분배한다.
5. `S5 제도 개혁` — 도량형·배급·세금·공사·기록 규칙을 바꾼다.
6. `S6 공동체 복구` — 수로·제방·창고·나루 같은 생활 기반을 함께 되살린다.
7. `S7 기술·기록 복원` — 사라진 공예·문서·지식·이름을 되찾아 다음 세대에 넘긴다.
8. `S8 약속 완수·평온한 이별` — 초자연 존재나 동물과의 약속을 지키고 경계를 세운다.

9. `S9 협상·교환` — 충돌하는 필요와 비용을 구체적인 조건으로 조정한다.
10. `S10 공개 실연·기술 대결` — 비교·재현·제작을 통해 실제 능력과 한계를 보인다.
11. `S11 공동 선택·연대` — 함께하는 행동이 협상력과 사건의 조건을 바꾼다.
12. `S12 포기·거절·철회` — 당장의 이득이나 잘못된 해결책을 버리고 대가를 감수한다.
13. `S13 규칙 재해석` — 앞서 제시한 규칙의 뜻을 다시 이해해 해결한다. 막판에 없던 예외를 만들지 않는다.
14. `S14 분리·경계 재설정` — 억지 화해 대신 합의한 거리·자립·돌봄의 한계를 세운다.
15. `S15 실패 인정·수정` — 틀린 판단이나 과정을 인정하고 행동을 바꾸어 다시 시도한다.
16. `S16 공로·이름 회복` — 지워진 사람의 기여와 정당한 몫을 돌려준다. 기술 자체를 복원하는 S7과 구별한다.

최근 7일 전체 생성 이력과 `핵심 모티프 태그 + 해결 엔진 + 결말 코드`를 비교한다. 이미 사용한 핵심 모티프 태그는 새 작품 후보에서 제외하고, 코드가 달라도 인과·반전·해결이 실질적으로 같으면 다시 설계한다. 네 안을 모두 `악역 자백→관아 판결→보상`으로 끝내는 것을 금지한다.

## 6. 4안 조합 규칙

1. `PERFORMANCE_SNAPSHOT: PASS`와 `PROVEN_SEED_MODE: PASS` 모두 HIT01~HIT08을 출발점으로 쓴다. 전자는 저장된 성과 자료에 2026-09-20 기준을 붙이고, 후자는 사용자 제공 검증 씨앗만 사용하며 공개 수치를 만들지 않는다. 최신 재조사는 메인의 명시적 요청 분기만 따른다.
2. 동일 장르 요청이어도 주 HIT 소재군은 네 가지로, 핵심 모티프 태그는 네 가지로 분산한다. 사용자가 특정 HIT 소재군을 지정한 경우에만 주 HIT를 고정하고 세부 사건 엔진 네 가지를 나눈다.
3. 네 안의 주인공 직업, 조력자 기능, 핵심 증거, 반전, 결말이 서로 겹치지 않게 하고, 5-7의 해결 엔진을 네 가지로 나눈다.
4. 동물 소재는 최대 2안, 초자연 소재는 최대 1안만 사용한다. 사용자가 특정 소재를 요청하면 예외다.
5. 참고 성과 영상 및 최근 7일 내 생성된 각 작품과 이야기 지문 7칸 중 4칸 미만으로 달라지는 안은 폐기하고 새로 조합한다. 핵심 사건의 인과·반전 원리·해결 수단이 같으면 이름과 소품을 바꿔도 통과시키지 않는다.
6. 추천 1안은 HIT 핵심 약속의 즉시 이해도, 첫 60초 시각화, 선택 구조 안의 기대 장면 3회, 핵심 전환의 의미 변화, 공정 단서, 피날레 보상, 정책 안전성을 함께 만족해야 한다. 성과 스냅샷을 사용할 때는 파일에 실제 기록된 성과 근거를 함께 비교한다. A~D에는 메인의 선택 규칙에 따른 주 구조·보조 작법·역할·선정 이유도 표시한다.
