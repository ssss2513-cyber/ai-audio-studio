# 야담 이미지프롬프트 제작 규칙 — 2.7.10

## 1. 고정 작업 순서
대본 접수 → 대본 전체 분석 → 화풍 선택 질문·사용자 선택 → 선택 화풍으로 에셋 18장 프롬프트 → 등록 에셋을 호출하는 본편 프롬프트 → 원문·화풍·ID·장면 검증 → 이미지 생성 여부 질문 → 사용자 승인 → 에셋 18장 실제 생성·검수 → 실제 에셋 참조 입력 → 본편 생성·검수.
이 순서를 뒤집거나 화풍·이미지 생성을 자동 승인하지 않습니다. 규칙 적용 요청은 이미지 생성 동의가 아닙니다.

## 2. 대본을 분석한 다음 화풍을 선택받기
원본 파일 전체를 먼저 읽어 장르·분위기·핵심 감정·인물·배경·시간·소품·사건 흐름을 분석합니다. 원본을 고치거나 후킹 대사를 본편 첫 문장으로 대체하지 않습니다. 로컬 키워드 분석은 1차 보조일 뿐 의미 검토를 대체하지 않습니다.
분석 결과를 바탕으로 다음을 묻고 답을 기다립니다.
“대본 분석이 끝났습니다. 화풍은 어떤 방식으로 정할까요?
1. 대본에 어울리는 추천 화풍
2. 원하는 화풍 직접 입력
3. 참조 이미지의 화풍 사용”
추천이면 상세 후보를 제시하고 사용자가 고르게 합니다. 직접 입력이면 지정 화풍을 상세화합니다. 참조이면 실제 첨부 이미지의 선·얼굴·표정·명암·팔레트를 분석합니다. 이번 작품에 쓸 화풍이나 이미지가 이미 명확히 지정되어 있으면 같은 질문을 반복하지 않습니다. 추천 1위를 자동 확정하지 않습니다.
기존 기본/절약형 선택은 유지합니다. 이미 선택한 모드는 다시 묻지 않습니다. 절약형도 원문·상세 화풍·ID·에셋 수·생성 승인 검사를 생략하지 않습니다.

## 3. 선택 화풍으로 에셋 프롬프트 총 18개 먼저 작성
인물·배경·소품 세 종류를 모두 포함해 합계 정확히 18장입니다. 인물만 18장이나 18장에 배경·소품을 추가하는 방식이 아닙니다. 종류별 배분은 대본에 맞추고 특정 배분을 모든 작품에 고정하지 않습니다.
대본에 존재하며 본편에 실제 필요한 대상만 등록합니다. 허구의 대상·무의미한 중복으로 숫자를 채우지 않습니다. 조건에 맞는 18개를 구성할 수 없으면 구체적 충돌을 알리고 컷 수·대본·에셋 수를 몰래 바꾸지 않습니다.
에셋 레지스트리에 id/kind/description/source_evidence/filename을 기록합니다. ID는 작품 내 고유하며 대소문자·철자·밑줄까지 그대로 유지합니다. 배경·소품을 인물 시트 안에 넣지 않습니다.

## 4. 인물 한 명은 통합 캐릭터시트 한 장
한 캔버스에 전신 정면·전신 후면 두 모습과 얼굴/상반신 정면·왼쪽45도·오른쪽45도·측면90도 네 모습을 모두 넣습니다. 여섯 독립 파일로 분리하지 않습니다.
모든 모습에서 얼굴·나이·성별·체형·머리·복식·색·장신구·화풍을 동일하게 유지합니다. 단순 배경에서 각 모습이 겹치지 않게 배치합니다. 대본에 명시된 외형 변화만 별도 상태로 등록합니다.
인물 시트 한 장을 에셋 한 장으로 계산합니다. 본편은 한 장면 이미지이며 통합 시트의 분할 구도를 따라 만들지 않습니다. STEP 1 UPLOAD도 인물별 통합 시트를 지시합니다.

## 5. 본편 프롬프트와 에셋 호출 ID
에셋 18개 프롬프트·레지스트리를 먼저 완성한 후 본편 프롬프트를 작성합니다. 본편은 기본 100컷이며 사용자 지정 수량을 우선합니다.
형식: `003 | 해당 컷 대본 첫 문장의 앞 30자 | @[배경ID] @[인물ID] @[소품ID] 실제 프롬프트`
앞 30자는 공백·문장부호 포함, 번호 제외로 원문에서 그대로 가져옵니다. 30자 이하이면 전체를 쓰고 임의 요약·말줄임표를 추가하지 않습니다. 매칭키와 원문 전체를 내부 자료에 보존합니다.
실제 존재하는 해당 컷 에셋만 호출합니다. 등록 ID = 컷별 asset_ids = 앞쪽 호출 ID = 본문의 같은 대상 ID = 실제 생성 도구에 전달하는 참조 ID 연결이 반드시 일치해야 합니다. ID 별명·임의 번역·자동 교정 금지. ID에 's/’s 등 접미사를 붙이지 않습니다.
인물은 실제 등장인물, 배경은 장소·시간, 소품은 화면에 필요한 대상과 일치해야 합니다. 원문 근거와 의미 판단을 기록합니다. 정규식이나 파일 해시 검사는 의미적·시각적 일치를 자동 보증하지 않습니다.

## 6. 프롬프트 완성 후 반드시 생성 승인 질문
에셋 18장과 본편 프롬프트를 모두 완성·검사한 뒤 결과와 예정 수량을 보여주고 다음 질문을 합니다.
“프롬프트가 완성되었습니다. 에셋 이미지를 먼저 생성한 뒤, 그 에셋을 참조해 본편 이미지를 생성할까요?”
이 작품의 현재 프롬프트 묶음에 사용자가 명확히 승인하기 전에는 에셋 이미지도 본편 이미지도 생성하지 않습니다. 화풍 선택·규칙 수정·파일 적용은 생성 동의가 아닙니다.
승인하면 에셋 18장부터 생성하고 실제 결과를 확인한 뒤 본편을 생성합니다. 같은 계획에는 반복해서 묻지 않습니다. 대본·화풍·에셋·프롬프트가 바뀌면 이전 동의를 새 계획에 재사용하지 않습니다.

## 7. 실제 참조 연결
에셋 18장 전부가 생성·검수되기 전에 본편을 생성하지 않습니다. 각 본편 요청에 필요한 인물 통합 시트·배경·소품의 실제 이미지 파일 또는 생성 도구의 유효한 이미지 식별자를 전달합니다. 프롬프트의 @[ID] 문자열만으로 참조했다고 처리하지 않습니다.
실제 파일 경로·해시·도구 참조 ID·검수 상태를 ASSET_IMAGES.json에 기록합니다. 누락·변경·다른 인물·중복 참조면 해당 컷을 중단합니다. API/도구에 실제 전달하는 것은 실행자의 작업이며 검증 코드가 API 요청이나 이미지 생성을 대신하지 않습니다.

## 8. 저장 방식
프로젝트 작업 폴더 아래에서 `output/assets/`와 `output/scenes/`를 구분합니다. 두 폴더는 승인 후 이미지 생성 단계에서 사용하며, 프롬프트 단계에서는 저장 계획만 만듭니다.
에셋 파일명: 인물 `영문ID_캐릭터시트.png`, 배경 `에셋ID_배경.png`, 소품 `에셋ID_소품.png`. 파일명 앞에 순번을 붙이지 않습니다. ID와 파일명 대응은 asset-plan.json에 보존합니다.
본편 파일명: 해당 컷 원문 첫 문장 앞 30자를 기본 이름으로 사용합니다. `003_` 같은 숫자 접두사는 붙이지 않습니다. 파일명 금지문자는 저장명에서만 공백으로 바꾸고 끝의 공백·마침표를 정리합니다. 원문 매칭키는 변경하지 않습니다. 이름이 같으면 `_중복2`, `_중복3`을 붙이고 컷 번호·원문 인덱스·매칭키·실제 저장명·에셋 ID를 image-save-plan.json에 보존합니다.
실제 PNG로 저장합니다. 다른 형식의 원본에 .png 확장자만 붙이지 않습니다. 실제 이미지 바이트 저장·변환은 생성 단계에서 수행하며, 이 프롬프트 도구만 실행하고 이미지 파일을 생성했다고 보고하지 않습니다.
최종 Flow 본문은 STEP 1 / UPLOAD / [대본 1~N] / ===프롬프트=== / [영어 프롬프트 1~N] 순서를 유지합니다. 내부 검증·질문·저장 계획은 Flow 본문에 새 섹션으로 추가하지 않습니다.

## 9. 유지할 품질 규칙
선택 화풍의 선·얼굴·표정·명암·팔레트 원문 전체를 매 에셋·본편 프롬프트에 유지합니다. 30자 제한은 화풍에 적용하지 않습니다. 기존 10종 화풍과 참고 이미지를 유지합니다.
본편은 서사·해설·교육적 가치 중 최소 하나가 실제 화면 표현에 드러나고, 불쾌감을 주는 연출을 보완해야 합니다. 원문에 없는 인물·소품·사건·날씨·밤 배경을 창작하지 않습니다. 실제 생성 결과를 검토하지 않고 시각 품질이나 유튜브 승인을 보장하지 않습니다.
본편 시작의 ‘옛날 옛적/옛날, 옛적’ 규칙을 유지합니다. 원문에 없으면 임의로 만들어 넣지 않습니다.

## 10. 실행과 적용 범위
담당 AI가 대본 분석·에셋 레지스트리·컷별 근거·사용자 답변을 기록합니다. 사용자에게 내부 JSON 작성을 시키지 않습니다.
대본 최초 분석은 --style-mode 없이도 실행할 수 있습니다. 후보 제시는 선택이 아니며, 최종 제작은 실제 사용자 선택을 요구합니다.
`gates.py --final`은 기존 검증에 에셋 18개·세 종류·ID·원문 근거·파일명 검사를 더하고 asset-prompts.txt/asset-plan.json/image-save-plan.json을 생성합니다. 질문은 파일 밖에 표시합니다.
생성 승인 질문 준비: `workflow_guard.py --root work --stage question`
실제 동의 기록: `workflow_guard.py --root work --stage approve --user-message "실제 승인 답변"`
에셋 생성 전 확인: `workflow_guard.py --root work --stage assets`
본편 생성 전 확인: `workflow_guard.py --root work --stage scene --scene 1 --request request.json`
이 명령들은 검사만 수행하며 이미지 생성·사이트 업로드·프로젝트 설정 UI 변경을 대신하지 않습니다. 각 완료 상태는 실제 실행 결과로만 보고합니다.
